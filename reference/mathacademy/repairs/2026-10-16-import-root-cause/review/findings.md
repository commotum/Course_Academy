## Scalable audit with falsifiable controls

1. Inventory **each owned source field**: topic, tutorial/example/question ID, prompt/solution/choice, exact source path/hash, visible top-level formula or asset, and source cell/control coordinates. Join to the archived JSON and original prepared field first, then to the current EDB entity/attribute. Keep historical and current affected counts separate.
2. Fingerprint meaningful structure, not source bytes alone: operands, relation/operator order, matrix dimensions and cell expressions, zero-rule versus ruled fractions, literal fences, statement labels, and control row/column coordinates. Whitespace, standard matrix-environment spelling, approved line wrapping, and authored color adjustments can differ without lost content.
3. Avoid duplicate formula counting: nested MathML inside an SVG title is part of its parent asset; TeX annotations/assistive MathML can duplicate the same visible formula; ordinary phantom contents are invisible. A complete saved SVG can satisfy fidelity even when it is not replaced by LaTeX. A mixed title's inner annotation cannot stand in for its whole visible equation.
4. Require a deterministic loss witness for automatic proposals: source has two factors/equality/result but the matched output has only one nested fragment; source has visible zero-rule notation but output introduces division; source cells/labels are demonstrably absent or reassigned. Valid lone matrices, ordinary fractions, plain lists, and equivalent complete source images are negative controls.
5. Generate guarded repair candidates only when current field equals the proven damaged version, or when a reviewed source comparison establishes the exact missing components. A changed current field, shared answer entity, ambiguous ownership, or unexplained mathematical difference must be reviewed. Preserve complete captured difficulties, answer-field IDs, choices, and correct links; targeted formatting repairs should not trigger wholesale capture replacement.
6. Validate in two layers: source-fidelity evidence first, then the actual UI at desktop/mobile sizes with all formulas, choices, control positions, and accessible horizontal scrolling checked. A successful MathJax render cannot replace layer one. Add exact positive and negative source fixtures for each newly confirmed converter defect.
