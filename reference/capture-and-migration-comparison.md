# Capture script and migration comparison

Here, **“captured” means saved by the script**, and **“migration work” means extracting, resolving, and transacting that evidence into `math`**. It does not necessarily mean we authored additional content.

| Area | What the capture script saved | What we did during migration |
|---|---|---|
| **Practice questions** | The problem, worked solution, observed difficulty, calculator instructions where present, MA question ID, knowledge-point association, answer fields, and images. Evidence included before-answer, after-answer, and completed-activity captures. | Deduplicated repeated `q-` identities across activities. Selected the latest complete source representation, reused existing `:question/id` UUIDs, and created genuinely new questions. Transacted **19,700 questions**, including **17,445 new identities**, and linked them through `:knowledge-point/questions`. |
| **Answer fields and answers** | The displayed answer-field types—`radio`, `select`, and `blank`—their locations in the problem, original choices, submitted answers, and available grading feedback. Normalized records could also contain solver-selected answers. | Prepared `:question/answer-fields` with `:answer-field/key`, `:answer-field/type`, `:answer-field/choices`, and `:answer-field/correct`. Established correct answers from MA evidence rather than trusting solver decisions. Preserved original choices without authoring distractors. Held **2,103 questions** whose complete correct answers could not be confirmed without interpretation. |
| **Canonical examples** | The demonstrated problem, worked solution, MA example ID, and associated knowledge point. Examples generally did **not** expose answer fields or difficulty; the script recorded those as unavailable. | Resolved `e-` identities and reused **2,820 existing example entities**, adding three new ones. Preserved the relationship through `:knowledge-point/canonical-example`. Missing source fields did not cause us to erase previously stored fields or invent new ones. Canonical examples remained outside the practice-question collections. |
| **Knowledge points** | Existing knowledge-point associations and, when encountered, new example IDs and knowledge-point titles. Those associations could contain references to the old database. | Resolved knowledge points against the new database using MA topic/example identities. Reused existing UUIDs and created **three new knowledge points**, with their titles, canonical examples, topic membership, and practice questions. Their placement within lessons required the additional lesson-structure work below. |
| **Tutorials** | Each encountered tutorial’s HTML in `tutorial-<id>.html`. This preserved instructional text and embedded formula/image evidence, but tutorials were not included as complete normalized entities in the question/example import payload. | Extracted `:tutorial/title` and `:tutorial/content`, preserving explanations, formulas, tables, and image locations. Transacted **1,998 tutorials**: **1,987 reused existing identities**, including one replacement on the same entity, and **11 were additional tutorials**. |
| **Images** | Questions and examples used the asset-saving routine, which saved available original image bytes, hashes, paths, and provenance. Tutorial HTML retained image references and inline SVG, but the tutorial branch bypassed that routine. | Copied images into `math/images/<first-two-hash-characters>/<sha256>.<extension>`, reused identical files, and rewrote content references to relative paths. Extracted saved tutorial SVGs and retrieved **35 missing graphics affecting 27 tutorials**, using each stream’s account. No image bytes were transacted into EDB. |
| **Lesson activities and steps** | The script navigated lesson screens and saved their content, but did not produce a complete lesson definition containing all verified placement IDs, ownership, and ordering. Tutorial/example content IDs were not sufficient to identify their steps. | Retrieved the **six affected topic pages**. Updated `:activity/steps`, `:activity/first-step`, `:step/content`, `:step/next`, and verified `:step/math-academy-id` values. Reused **28 step UUIDs** and added **14 steps** for eleven tutorials and three knowledge-point sections. Updated titles and example ordering. The replacement tutorial and its step retained their existing UUIDs and history. |
| **Multisteps** | Shared setup, diagrams, individual question problems, question order, and topic/knowledge-point associations. The old importer primarily imported their questions rather than reusable activity structure. | Prepared **28 multisteps**, using `:multistep/context`, `:multistep/steps`, and `:multistep/first-step`, with ordering through `:step/next`. Created assigned-problem references and enclosing assignment activities. The structure was a schema translation; the context, questions, and part order came from MA. |
| **Assessment and diagnostic activities** | Introductory HTML, served questions, some activity identifiers and metadata, and completion evidence. This described particular attempts, not necessarily complete reusable activity definitions. | Preserved **28 distinct instruction bodies** as tutorials. Imported confirmed question content, but did not infer complete assessment question collections or diagnostic routing from individual attempts. Incomplete definition evidence remained in `reference`; learner results, timing, XP, and mastery were excluded. |
| **Our corrections and source attribution** | Original MA evidence alongside solver predictions, answer reconciliation, and some later correction records. These could be mixed in normalized content. | Reconstructed the MA-original values, **including source errors**, and transacted them with `:org/Math-Academy` as source. Prepared **74 separate correction drafts** for later transactions under an assistant source. Those corrections remain unapplied. |
