# Quality audit: 99 topics, 2026-10-28

Completed using three disjoint subagents and EDB. The scope contains **99 topics, 7,844 questions/examples, 242 tutorials, 311 knowledge points, and 265 initially registered generators**. All 41 scoped multistep parent statements were also checked. The baseline was T9837; consolidated readback is T10144.

## Repairs applied

The committed batches made 4,709 guarded scalar assertions (4,699 distinct entity/attribute pairs), created 3 independently derived owned canonical answers for empty blank banks, and removed 32 obsolete duplicate field memberships. Their entities and histories remain present. The resulting 9,059 active fields have unique keys and owned canonical answers, with no unkeyed fields or missing worked solutions remaining. These counts include source notation and formatting restorations; they are not a count of distinct mathematical errors.

The substantive defects included lost cross-product/curl operators, a hidden alignment minus imported as a coefficient, a visible boxed placeholder discarded as spacing, matrix response frames flattened from source HTML tables, an answered historical capture leaking into the problem, missing canonical links/solutions, and stale generated notation. Source font roles, set braces, highlighting, and formula fences were restored where the original capture established them. Intentional source illustrations and valid authored notation variants were retained.

Independent mathematical corrections were kept separate from source restorations. Examples include a contradictory parameter bound, an arccos domain intermediate that incorrectly excluded endpoints, a function label missing its third argument, an ambiguous free-coordinate question clarified without changing its bank or answer key, and a square-root kernel nonreal on an open subset of its stated solid. The latter was amended consistently across its prompt, solution, and all five choices, with a separate algebraic typo corrected. Full start-point, interval, orientation, and component constraints were checked before judging alternative parameterizations valid; no radio-to-checkbox migration was warranted.

## Preventing recurrence

**55 generator registrations were repaired across 56 published immutable versions**, with immutable digest verification and probes of the actual installed entrypoints. Affected successors were checked outside the repository from two package locations and different output directories, including owned UUID and served asset-byte stability. Frozen per-group manifests document supported difficulty/template coverage and independent mathematical checks. Unaffected packages were sampled through their supported APIs; this is not a proof of every possible random draw.

Generator fixes also remove output-path-dependent identities and missing local runtime dependencies. A deployed plot-renderer probe exposed a provenance write inside its immutable package; its superseding version writes to the caller output directory. All affected normal difficulty bands were checked under read-only package permissions, and the determinant generator now rejects an unavailable explicit selector directly while preserving normal hard practice and source replay.

The question capture and historical importer now distinguish bare hidden MathML spacing from a decorated visible box. Authentic regression fixtures protect the phantom-minus and boxed-placeholder cases; a separate ordered-operator regression protects curl and scalar triple products. The generator and capture documentation now requires full task constraints, operator-role preservation, source identity verification, and archive discovery that includes hashed history captures and valid previous copies. Solution completeness now checks absent attributes separately from empty strings or valid answer keys; source-domain checks distinguish real improper integrals from nonreal kernels on an open subset.

The shared grader now admits and compares supported whole polynomial circle equations after rearrangement or nonzero rational scaling, and recognizes the imported Unicode multiplication glyphs. Wrong centers/radii remain rejected. These engine changes passed the full unit suite and read-only answer-preview API checks. The application was restarted with the repaired learning binary; no QA attempts, XP, exposure, or timing records were created.

## Verification and limits

- Consolidated native grading: **9,059 accepted canonical checks, 27,143 rejected incorrect checks, zero unresolved**. Selection checks verify the actual owned answer identity dispatch; independently derived mathematics is recorded separately in the group proofs.
- Strict actual-player rendering: **52,153 fields, zero unresolved TeX commands or leaked display fences**. Stored learner keystrokes are not treated as authored math.
- Source assets: 4,091 unique served files, 8,182 desktop/mobile decode and overflow checks, zero missing assets. Actual question controls, including every scoped checkbox label and matrix/rich blank layout, received separate viewport checks in the group reports.
- Regression suites: 247 engine unit tests and 46 focused importer tests passed; read-only native/API circle and multiplication checks passed.
- Every original question, field, and answer UUID was retained; the original topic/KP pool links remain. Each write used compare-and-set or full-membership guards, native speculative preview, an explicit agent source, stable request identity, exact receipt-datom comparison, and readback. Detached banks were checked for current and retained learner-response history at the guarded write basis.
- Original problem captures were available for **4,112 of 4,221 source-ID records**. The remaining **109 lack a retained original prompt**; solution-only or bank-only evidence was not counted as an original prompt. Their current structure, rendering, and grading contracts were checked, but source fidelity cannot be certified without the missing material. The other 3,623 records are generated and have no original MA question ID.
- All visible strings and response contracts were audited. Mathematical proof is family-specific and strongest for changed content and affected generator families; this report does not claim an independent symbolic re-solution of every unchanged question or every tutorial intermediate.
