# Capture principles

1. Prioritize progress: an unfinished activity can block Math Academy's queue. Recover automatically without asking Jake, retaining the unfinished activity. Repeated failures must change the recovery strategy; unchanged retries do not count as progress. Expose persistent blockers and back off rather than repeating ineffective actions indefinitely.
2. Make fault tolerance and resumability part of every phase. Save progress and decisions, and track attempted entry, confirmed submission, grading, and completion separately. Resume from confirmed events without repeating accepted actions; an entry failure is not a learner attempt. Respect manual stops.
3. Resolve every question within its activity through a competent agent. Record a final judgment even when the question is genuinely unanswerable. Preserve the planned answer policy unless a specific, evidenced obstacle prevents continuation or the mathematics cannot support an intentional error. Missing source answers alone do not justify an override. Record the obstacle and limit the override to the affected question; preserve uncertainty regardless of what is submitted.
4. Python runs the workflow and detects exceptions. Agents answer specific questions; Python checks their results before acting.
5. Keep each phase focused. Use explicit records between phases and share common operations. Add complexity only when the capture requires it.
6. Preserve Math Academy's originals and attribution, including errors. Keep our reasoning, corrections, and calculated values distinct. Never turn a guess into a confirmed answer.
7. Follow the schema's entities and terminology. Reuse existing UUIDs when content changes so its history stays together.
8. Keep capture evidence and learner observations under `reference/` for later use. Store original images once by hash in `math/images`, and reference those files from content. Deduplicated storage does not merge source identities: retain each image's source URL and occurrence in the prompt or answer choices.
9. Let Database Commit own writes. Preview, commit, and verify; make retries safe. Persist pending database work so a temporary outage cannot block further capture or be mistaken for a successful import.
