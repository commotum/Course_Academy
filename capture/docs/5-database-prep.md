# 5. Database Preparation

Python turns the checked capture into reviewable transactions for `/media/jake/SSD/EDB/math`. It detects exceptions and calls an agent only when a database identity or revision match needs judgment.

1. Read the checked capture and the current database at one recorded basis. Validate source content and the agent's completed answer judgments. Any newly discovered source gap returns directly to Activity Capture's agent for a final judgment now; do not create a held-question queue or fill it with a guess.
2. Convert source content to Markdown with LaTeX and build answer fields from the confirmed choices and answers. Preserve Math Academy's content, including errors, and the separately recorded disagreements.
3. Hash original image bytes with SHA-256 and copy them to `math/images/<first-two-hash-characters>/<full-hash>.<extension>`, reusing identical files. Rewrite content references as `images/...` relative to the database folder and verify every image exists.
4. Match known source identities and reuse existing UUIDs. Existing questions are fill-only: preserve every populated question attribute, answer field, choice collection, correct-answer link, and owned answer value. A complete question remains an activity reference without content or knowledge-point changes. Only wholly absent components may be supplied from verified source evidence; a different value or rendering is not a missing component. Missing worked solutions alone do not make a question eligible for recapture updates. Python detects ambiguous identities and sends only those cases, candidate entities, and source evidence to an agent. If identity cannot be established, preserve existing entities and omit the disputed mapping with the agent's final reason.
5. Prepare the schema relationships: knowledge-point question pools and canonical examples, lesson content references and step order, and multistep shared context and ordered parts.
6. Calculate `topic/difficulty` from the lesson's base XP and the [agreed workload formula](../../reference/xp-docs/expected-distribution-base-xp.md), retaining the selected questions, inputs, and formula version.
7. Build EDN containing the required changes. Attribute Math Academy's original content to `:org/Math-Academy`. Keep calculated metadata separate with its own source attribution. Preserve the agent's decided corrections separately; any later correction transactions follow the originals under their own source. Original-content import never waits for Jake to judge a disagreement.
8. Validate entities, answer fields, references, ordering, images, and attribution. Pass complete batches and the database basis used to Transaction/Commit. When the agent's final judgment establishes that required evidence is unavailable, omit the affected content and dependent references with an explicit reason; do not import partial questions or pretend an answer is confirmed. Continue with the supported content. If there are no changes, record and report that result to the capture loop.

Steps 1–8 are scripted in Python; step 4 includes the conditional agent call. Content interpretation and source-page recovery belong to Activity Capture. Keep learner attempts, XP/progress observations, and reasoning as evidence for later import. Save preparation notes with the captures under `reference/`. Previewing and committing transactions belong to the next stage.

Source-backed reference practice can supplement a missing KP pool through `reference_questions`. Validate its original question and explicit answer metadata or actual reference grade, and retain that provenance. These are catalog records: keep them out of the captured activity's question order, attempts, timing, and difficulty sample. They need complete gradable fields, but need not invent a worked solution when the reference source supplies only an answer. Encountered activity questions still require their complete history solutions.

An explicitly authorized historical content-only repair is a separate scope: import verified original problem and worked-solution text with its original knowledge-point link, leaving unavailable answer fields unset. The seven historical factorial questions use the narrowly bound [fieldless repair](../scripts/fieldless_factorial_repair.py), which checks the frozen source inputs and uses Database Commit's normal preview, lineage, receipt, pinned readback, and no-op verification. These records are readable content and cannot serve as graded practice until their original controls are recovered. This exception does not change automated capture completeness checks, invent choices, remove existing controls, or declare the historical activity fully imported.

A missing knowledge-point ID is not a shared identity: resolve each history question separately. Preserve an existing question's captured knowledge-point ownership. For a new question, when the same capture includes one canonical example with the question's observed knowledge-point title and topic, use that source example to resolve the point. Preserve existing UUIDs. For revisable activity metadata, repeated scalar observations replace earlier planned assertions and retractions even when the final value agrees with the initial database snapshot; importing the same capture again must settle to no changes.

Persist the completed capture before preparation. If the database is unavailable, retain this work for automatic retry while capture continues. Read a fresh basis when preparation resumes; pending database work must not lose an activity or cause it to be repeated. Broad assessments read topic and activity relations in batches of at most 25 topics at that same immutable basis. This reduces time spent holding the import lock without changing transaction ordering or write ownership.

Live questions whose source identity could not be reconciled remain distinct capture records. A capture-local key is evidence identity, not a Math Academy question ID. Match each such record to its own final judgment; do not collapse all missing IDs into one question or borrow another record's judgment. Omit unsupported records and affected structural references with their individual reasons while continuing with supported content and later imports. Preserve the originals for future reconciliation.

Reusing a cached original image requires its bytes to match the recorded SHA-256. Activity Capture can refetch and repair a corrupt file in its saved asset cache. Preparation verifies the bytes when publishing to `math/images` and rejects an existing file that differs from its hash. Rendering repairs and recovered display copies must retain their provenance and must not be substituted for original source bytes without attribution.

The rebuilt database has no `answer-field/presentation` attribute. Keep any captured presentation hints in the original evidence; do not transact them or use them to distinguish otherwise identical answer fields. Reuse existing field and answer UUIDs when only a presentation hint differs.

Recapture is not a revision mechanism. Do not replace or remove an existing field, change its type or key, replace its choices, change its correct answer, or rewrite an answer value or feedback. Preserve those entities and their learner-response ownership even when the new source differs. A missing correct-answer link may only be filled when the captured source agrees with the retained field and choices and identifies the answer unambiguously. Ambiguous or incompatible gaps remain unchanged; they do not justify rewriting the existing structure. Deliberate content or display repairs require a separate authorized repair, not an automated recapture.

Before planning question or knowledge-point changes, check active facts at the preparation basis for separately attributed question, field, and owned answer content. Preserve any non-Math-Academy authored content, including equal values claimed by both sources, with a final `separately_attributed_correction` omission; retain the captured originals and continue with supported siblings. UUID-only attribution and retired answer entities do not establish an active correction.

Preserve separately attributed tutorial attributes as well. A recaptured lesson can continue to reference the existing tutorial, but must not replace its corrected content with a source image or reattribute the correction to Math Academy.

[Source validation](../scripts/database/evidence.py) rejects either explicit incomplete-field flag (`answer_fields_complete: false` or `fields_complete: false`) and missing controls referenced by normalized field placeholders. An answer judgment cannot establish that uncaptured fields do not exist. Preserve existing omitted fields when an otherwise supported update has no completeness declaration; do not use that preservation rule to import an explicitly incomplete question.

Also reject a declared authored problem field whose normalized placeholder is absent. This catches lost sibling problem sections even when their controls were extracted successfully.

[Preparation's final judgments](../scripts/database/prepare.py) are bound to the current source evidence, exact gap, record kind, and question or capture-local identity. An earlier answer confirmation alone cannot close a newly discovered source gap. Exact retries reuse the durable decision; changed evidence or a different gap requires a new finding. A repair must still pass source validation, and a different gap exposed by that repair receives its own final finding. If required evidence remains unavailable, preserve the finding and omit affected content and dependent references while processing supported content.

After the import verifies or settles to no changes, persist accepted preparation answer repairs back into the capture's raw answer fields. Require the exact original source-evidence hash and archive the original content under `database/source-repairs/` first. Retain raw source paths rather than database-rendered replacements. Do not revise the package while an immutable submission request is unresolved, or during preview-only processing. This keeps the captured source evidence consistent with the checked database import.

A concluding sentence does not supersede the rest of a contradictory worked solution. If that conclusion is absent from the captured choices, the agent may cite an earlier completed source calculation or complete statement judgments that unambiguously determine one current choice, explaining any equivalent form. Keep the finding `source_error`, preserve the original wrong conclusion and prior interpretation, and label the answer evidence `worked_solution`; this does not confirm the site's grading key. Mathematical reasoning from the problem alone is insufficient. If no complete source result supports an available choice, retain the omission. Final-judgment caching includes the interpretation policy so an obsolete finding cannot prevent a fresh source review.

[Live/history merging](../scripts/activity/evidence.py) distinguishes current extraction failures from preserved error history. A successful recapture can retire a transient failure only for the same question and the source sections it actually reread. A missing error report or a solution-only read cannot clear unrelated problem or field failures. Preserve the original artifacts, error provenance, and authored Math Academy errors; recovery changes the current extraction status, not the source's history.
