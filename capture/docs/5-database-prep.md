# 5. Database Preparation

Python turns the checked capture into reviewable transactions for `/media/jake/SSD/EDB/math`. It detects exceptions and calls an agent only when a database identity or revision match needs judgment.

1. Read the checked capture and the current database at one recorded basis. Validate source content and the agent's completed answer judgments. Any newly discovered source gap returns directly to Activity Capture's agent for a final judgment now; do not create a held-question queue or fill it with a guess.
2. Convert source content to Markdown with LaTeX and build answer fields from the confirmed choices and answers. Preserve Math Academy's content, including errors, and the separately recorded disagreements.
3. Hash original image bytes with SHA-256 and copy them to `math/images/<first-two-hash-characters>/<full-hash>.<extension>`, reusing identical files. Rewrite content references as `images/...` relative to the database folder and verify every image exists.
4. Match known source identities and reuse existing UUIDs. Python detects multiple possible matches, conflicting mappings, or possible revisions with changed source IDs. It sends only those cases, candidate entities, and source evidence to an agent. The agent decides the best supported match; Python checks the references and consistency before accepting it. If identity cannot be established, preserve existing entities and omit the disputed mapping with the agent's final reason. Missing captured fields must not erase existing content.
5. Prepare the schema relationships: knowledge-point question pools and canonical examples, lesson content references and step order, and multistep shared context and ordered parts.
6. Calculate `topic/difficulty` from the lesson's base XP and the [agreed workload formula](../../reference/xp-docs/expected-distribution-base-xp.md), retaining the selected questions, inputs, and formula version.
7. Build EDN containing the required changes. Attribute Math Academy's original content to `:org/Math-Academy`. Keep calculated metadata separate with its own source attribution. Preserve the agent's decided corrections separately; any later correction transactions follow the originals under their own source. Original-content import never waits for Jake to judge a disagreement.
8. Validate entities, answer fields, references, ordering, images, and attribution. Pass complete batches and the database basis used to Transaction/Commit. When the agent's final judgment establishes that required evidence is unavailable, omit the affected content and dependent references with an explicit reason; do not import partial questions or pretend an answer is confirmed. Continue with the supported content. If there are no changes, record and report that result to the capture loop.

Steps 1–8 are scripted in Python; step 4 includes the conditional agent call. Content interpretation and source-page recovery belong to Activity Capture. Keep learner attempts, XP/progress observations, and reasoning as evidence for later import. Save preparation notes with the captures under `reference/`. Previewing and committing transactions belong to the next stage.

Persist the completed capture before preparation. If the database is unavailable, retain this work for automatic retry while capture continues. Read a fresh basis when preparation resumes; pending database work must not lose an activity or cause it to be repeated.
