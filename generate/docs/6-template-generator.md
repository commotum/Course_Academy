# 6. Template Generator

Treat imported formatting as evidence to normalize, not a template to copy blindly. In prompts, worked solutions, text choices and feedback, delimit every equation with `$...$` or `$$` display delimiters. Use `$$` plus `\begin{aligned}...\end{aligned}` for multirow derivations and preserve `\\` row separators. Never emit bare environments, `[math]` wrappers, indented math/code blocks, or unescaped currency/percentage glyphs. Normalize prose with `scripts/question_capture/math_format.py` before calculating content identities, then validate it; math answer values remain bare TeX. Render through the actual UI and verify that every intended equation and row appears, with no raw TeX outside math containers. Zero MathJax errors alone does not establish successful rendering: an unrecognized block can produce no error at all.

Use the templates from [Template Extraction](4-template-extraction.md), including any attached plot specifications. Start with one Python script in `generate/scratch/<knowledge-point-db-id>.py`, with documented sections for each difficulty and shared helpers.

For matrix-entry questions, use `matrix_operands()` and `matrix_answer()` from [math_format.py](../../scripts/question_capture/math_format.py). Put separately wrapping, centered given matrices below the prose. Render the answer as a borderless rectangular matrix with external brackets and the expression outside it. Pass bare TeX for supplied entries and the existing `{{field-key}}` placeholders for editable entries, preserving row and column order. Do not use padded Markdown tables, blank label columns, or spreadsheet grid lines. Radio choices remain their existing matrix answers.

1. Use SymPy for exact symbolic work, seeded randomness for reproducible sampling, and Matplotlib for plots, with TikZ when needed.
2. Design and sample eligible answer-bearing assignments or decision cases before filling incidental values and presentation details, unless the mathematics requires a different order. Implement seeded samplers for the extracted slots, including eligible targets or positions as well as values. Preserve the backbone, slot roles, constraints, and field types; explicitly label supported generalizations or narrower sampling policies.
3. Instantiate the source's ordered solution steps within the lesson and its prerequisites, then derive the final answer, intermediate values, distractors, and plot data from that same instance. Use symbolic computation to verify those steps and values separately from rendering them.
4. For choice fields, select an eligible source bank profile and apply all its mapped recipes; for blanks, produce the exact required answer fragment.
5. Render the template's prompt structure, field placeholders, answer values, and shared instructional sentences from the same sampled instance. Only `blank` and `select` fields use `{{key}}` prompt placeholders. Radio, checkbox, and free-response controls render separately: never append their widget markers. When a radio question asks for a missing component inside a formula, show `?` at that position. Parameterize target references throughout the prompt and solution, producing one concrete worked solution independent of the learner's chosen answer.
6. If new plots are required, call [Plot Generator](7-plot-generator.md) with the same instance data and insert its returned assets; otherwise reuse unchanged assets or continue without plots.
7. Expose generators by difficulty and template, with seeded Markdown and JSON previews containing the question, fields, answers, and reproducibility metadata.
8. Replay every source question at its original parameters and bank profile, comparing its complete generated answer bank with the original bank.
9. Check every supported template, field combination, and bank profile for mathematical correctness, actual grading, parameter boundaries, profile selection, formatting, plots, deterministic replay, backbone preservation, and coverage of the declared variable slots.
10. Before handing the generator to an independent reviewer, run the author’s own decision-relevant variation and shortcut checks described below. Repair any discovered incidental predictor and rerun the affected checks. Report fidelity, correctness, grading, and pedagogical variation separately, then compare originals and variants side by side before declaring the package ready.

Resample parameters when they produce invalid or ambiguous questions. Preserve the source choice count, blank answer shape, notation, and solution sequence; keep inferred error recipes out of the learner presentation unless the source includes feedback.

Treat the displayed answer form as part of the instructional contract. A CAS normal form can introduce identities or methods the learner has not been taught, even when it is mathematically equivalent. Preserve operator inputs and the solution's final form in the keyed answer; do not independently simplify the bank into another representation. If a conversion is required, verify that it is within the lesson or its prerequisites and show it in the worked solution. If it is outside scope, preserve the original form rather than adding the new skill. Check rendered arguments and the final-solution-to-answer transition independently of algebraic equivalence. Include a regression where symbolic normalization would otherwise reverse a trigonometric argument or introduce another unshown identity.

For substitution generators, define difficulty by the learner's work: recognizing the inner function, matching its derivative, handling its constant factor, changing bounds, and evaluating both endpoint contributions. Record imported labels separately from authored band decisions. Larger coefficients alone do not establish a harder band. Choose and balance supported substitution/function/endpoint families before numerical parameters; reject amplitude-only clones in the delivered batch. Audit conditional shortcuts such as a recognizable family always evaluating to zero or always having one zero endpoint contribution. Keep derivative notation in familiar prerequisite forms rather than introducing equivalent trig identities through CAS printing.

Calibrate against what the learner must do before feedback, including the support in the question and its response format. A supplied substitution followed by choosing the transformed integral is a different task from finding the complete exact answer. For an authored progression, retain a matched pair with the same mathematical instance and identify the added target decision or removed support. Keep prerequisite arithmetic and recall familiar: a harder band should add one justified target condition while other components stay controlled. Do not stack fractional amplitude, fractional slope, shifted bounds, quadrant recall and unlike radicals to manufacture a hard band. Supply primitive formulas or endpoint facts when their recall is outside the assessed skill. Inspect rendered parameters and the resulting arithmetic; raw slot ranges and large answer counts do not establish a reasonable workload. Compare against at least two complete imported examples per band when available; a nearby KP can supply pedagogical evidence when the target has missing bands. Preserve the distinction between imported anchors and authored inference.

Use one derivation to render the final worked result and canonical answer. Show any logarithm power/quotient conversion and any renaming of an integration constant; never silently drop a source's explanation when rebuilding its solution. Normalize accepted aliases after transformation, deduplicating those that become identical. A defective imported distractor bank does not by itself disqualify its valid mathematical family: document a repaired or explicitly authored response contract instead of freezing the whole family out. Retain the original bank and source replay evidence without claiming that an authored replacement bank or response format is a faithful replay.

For newly authored antiderivative blanks, prefer the existing external `$+C$` response contract, with the canonical answer containing only the requested fragment. Verify the final full solution against that fragment plus the displayed constant. Exercise the actual grader with an expanded answer that absorbs a back-substitution constant, as well as a wrong nonconstant term and a changed-domain answer. Literal key replay alone does not establish grading compatibility for antiderivative families.

Every learner-facing checkbox question must have at least one mathematically correct selectable option. When a captured Math Academy question offers “None” (or an equivalent explicit answer such as “no vertical asymptotes”), preserve it as a visible checkbox, including when it is a distractor. Key it true exactly when none of the ordinary options is correct. A correct visible “None” counts as a correct selectable option; leaving every box unchecked does not replace it. Source replay must preserve that choice. When adding it to existing questions, map saved responses to the new Boolean field from the learner’s actual selected subset and preserve grades and other learner state.

For a checkbox family with reviewed source None evidence, `nonempty_checkbox(generate, none_label='None of the above')` preserves that visible option, derives its key from the ordinary options, and assigns fresh owned identities for the changed response shape. Retain the source evidence with the generator. Other families keep the default rejection policy.

For newly sampled variants, exclude decision cases that would leave no correct selectable option, including explicit parameter paths and finite catalogs. Do not manufacture a “None” option to rescue an invalid generated question. Use the shared nonempty policy in `scripts/generator_policy.py` as a final guard; immutable packages must declare and bundle that helper. Publication and fresh-practice selection independently reject empty correct checkbox subsets; historical responses retain their original meaning.

Implement the declared slots directly. Keep one source of instance data for selected targets, labels, values, and their relationships; validators must enforce the mathematical role of a slot rather than require its original example value. Source replay at original parameters establishes fidelity. Normal sampling must exercise the permitted slot domain while preserving the same method and structured presentation. Do not add arithmetic operators, response types, or reasoning stages absent from the extracted backbone just to increase variety.

Validate variation per declared slot, not only by counting distinct whole questions or matrices. Report sampled target positions and roles where those are variable, and account for eligible choices that never occur. Check the relevant bounded domain or representative cases without requiring every combination of continuous or large domains. For a fixed component, check that its intended role stays fixed. Include a changed-target case with the other mathematical data held constant, independently reading the rendered prompt, worked solution, and answer key; it must catch stale target references and keys. Correct numeric answers, many changed coefficients, or successful source replay alone cannot establish coverage of other declared slots.

Audit the specification itself: a declared fixed role may be an unjustified source-example detail. In the independent review, require a separate `decision_variation` check supported by `pedagogical-variation.json`. Record the learner operation, reasons for fixed features, eligible answer-bearing roles, decision-case coverage, controlled counterfactuals, shortcut probes, delivery-stage checks, and limitations. Include reproducible scripts and sampled records. Vary relevant evidence while holding other data fixed, checking the predicted response change and its agreement with the prompt, explanation, and actual grader. Also change irrelevant evidence and check response preservation where meaningful. If a counterfactual is outside scope or no irrelevant feature exists, justify that limitation explicitly.

Probe answer-producing strategies as well as literal answers: "choose A", "select the last two", or "use the first number" can stay reliable while numerical answers vary. Test cues such as labels, option positions, response counts, layouts, and template identity within each recognizable template or subgroup, reporting successes, attempts, and the comparison baseline. Overall answer balance cannot establish conditional variation. A reliable incidental shortcut requires repair even if source replay, correctness, and uniqueness pass. A valid mathematical simplification that exercises the target skill is acceptable; explain the distinction using the lesson evidence rather than imposing arbitrary answer-balance quotas.

Inspect questions after the actual rejection, deduplication, difficulty, and inventory-selection rules. Use a read-only reproduction of those rules when publication has not occurred, retaining the sampled batch and stage counts; do not write to the database to test it. Compare decision-case and shortcut coverage before and after filtering, and name any inaccessible stage as a limitation. Raw sampler support alone does not establish that learners receive that variation.

Select side-by-side review examples that demonstrate the declared variations and preserve the backbone. For the route-matrix example, show different eligible loop and directed cells, with letter assignments and solutions agreeing, while keeping `a+b+c`, three unknowns, and the same counting stages. Cosmetic label or option shuffles alone do not demonstrate different assessed relations.

Do not take the first valid recipes from a pooled list. Choose a complete profile before constructing its bank, then reject or resample the instance if any required option is correct, equivalent to another option, or otherwise invalid. Any mixed-profile bank is an explicitly labeled extension. Record the selected profile and recipes in reproducibility metadata, and ensure different authored banks cannot collide under one question identity; seed changes and option shuffling alone still do not create new questions.

Source-bank replay must match every original option to exactly one generated option, ignoring order while preserving choice count and the correct designation. Compare complete mathematical objects: equations may be equivalent under multiplication by a nonzero constant, and domains and branches must be respected. Comparing equation sides independently is insufficient. Keep rendered notation and solution-layout checks separate from algebraic equivalence.

Report matched/total source distractors and complete banks per template and profile, with every missing or extra option identified. Require full coverage for supported source banks before declaring fidelity or passing output to database preparation. Source errors need recorded evidence and a supported correction or explicit exclusion; unresolved comparisons remain failures. Correctness tests and radio ID-selection tests cannot satisfy this requirement.

Exercise every profile under its applicable parameter conditions, including zero/nonzero shifts, equal/unequal scales, and signed values where relevant. Check selected banks, not merely candidate recipe availability, so later profiles cannot be silently excluded. Vary parameters to check that recipes generalize rather than copying source literals; sparse source evidence still limits what can be inferred.

For blanks, test accepted equivalent entries and rejected incorrect entries with the actual learner grader. SymPy checks in the generator do not establish engine grading compatibility.

Use the existing question, field, and answer representations, with field-owned answer identities and delimiter-free mathematical values. Record generator version, dependency versions, seed, parameters, domains, and source references separately from those records. Keep drafts and assets local for review, then pass validated instances to [Database Preparation](8-database-prep.md).
