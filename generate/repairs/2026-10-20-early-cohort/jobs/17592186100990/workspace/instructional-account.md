# Instructional account and repair design

The learner locates one boxed matrix entry, counts its one-based row from the top and column from the left, then selects the indexed symbol or enters that symbol or the two indices. No arithmetic on entries is required. The tutorial “Introduction” (34f3a63d-a273-50fb-b26a-ae172c7e93e9) says “The first subscript represents the row and the second subscript represents the column.” “General Form of a Matrix” (775ac64e-8b63-5c51-824d-1d99d17a2a0a) defines every entry for i=1,...,m and j=1,...,n. The canonical e-4373 illustrates (1,3); preceding lesson examples find a value from coordinates. This task reverses that lookup, without requiring new prerequisites.

Source families: inline radio q-13498 (9fd0e65a-fdf4-5ff0-b32a-cc8e1d649563), q-13503; display radio q-13489, q-125611, q-13499; symbolic blanks q-279553 (36238d70-96e9-5c96-9f9b-52eb899b35f4), q-279556 (a5eb6b6d-276d-54a5-b401-53f9f0ed2a3f); two numeric blanks q-139426 and q-139629 (7e0025f5-b24a-57c0-a91e-70e60e6e725f). All nine complete source banks will be replayed, with restored highlights where captures omit them. q-139629 has matching keys i=3,j=1 and solution, sufficient evidence to restore its missing highlight. Its 4x4 shape is observed easy evidence. q-13498/q-13503 lack keys and solutions; the supplied source highlights determine the keys, and the common positional solution supplies their completion. Existing legacy raw replay remains evidence-only. No diagrams are needed: the matrices are TeX.

Fixed features have instructional reasons: one highlight makes the target unambiguous; row then column defines the notation; five radio choices preserve observed response workload; two numeric blanks preserve separate row/column responses; the worked solution identifies row, column, then notation/value. Original source difficulty labels are preserved. Easy supports the observed small shapes 2x2, 2x3, 3x3, 3x4, 4x2, 4x4. Existing moderate/hard authored scan extensions remain available but are not source-rated or validated by this easy repair. They must not be represented as observed difficulty evidence.

The answer-bearing role is the highlighted cell, not an offset in an answer bank. Source banks are finite coordinate arrangements, not proof that a particular slot must be correct. Preserve their exact source replay. For normal radio variants, choose the complete bank arrangement and its placement first, then choose any of its in-matrix cells as the highlighted target. Require at least two eligible cells so that even dimensions plus bank cannot determine the answer. Coordinates outside the matrix can remain distractors, as observed in q-13503/q-13489/q-125611/q-13499. This is a conservative extension: every bank retains its five-coordinate shape while the role of correct option changes. Translation, eligible target changes, matrix letter and incidental integer entries preserve the same lookup and response workload. Blanks allow every cell, including corners, diagonal and off-diagonal positions. Entry changes alone preserve the response.

Finite CLI batches pair radio records with a shared bank and distinct eligible targets. This supplies an actual counterexample to any bank-only choice rule in each included radio group, rather than relying on favorable seeds. The remaining singleton in an ordinary odd-sized batch uses a source-supported blank. Explicit source-replay requests remain exact and exempt from practice batching. No semantic duplicates or special reported seeds are used. Radio fields still have exactly one correct choice; that count is inherent to the response contract, not evidence of varied reasoning.

Validation obligations: replay every source matrix/bank/key/solution; independently recover boxed coordinates and keys; change highlighted target holding values, label and bank fixed; change only entry values preserving response; test each eligible target within each fixed bank geometry; inspect position, row/column rank and bank-shape predictors before/after shared delivery filtering; rerun the retained cue check on current CLI output. Native grading must accept braced/unbraced-base indexed symbols and reject wrong indices, letters, missing indices, and numeric entry values. The engine repair treats subscripted symbols as distinct formal variables rather than ignoring a subscript or doing arithmetic on its digits.

## Comma-index grading repair (2026-10-22)

The exact delivered counterexample rejects `c_{2,2}` for the same cell keyed `c_{22}`. Source questions q-279553 (36238d70-96e9-5c96-9f9b-52eb899b35f4) and q-279556 (a5eb6b6d-276d-54a5-b401-53f9f0ed2a3f) require an indexed symbol; the Introduction tutorial (34f3a63d-a273-50fb-b26a-ae172c7e93e9) assigns row and column to the first and second subscripts. Separating those two indices with a comma preserves the same ordered coordinates and lookup workload. Comma notation is a mathematically equivalent response extension, not a different generated source family. The generator, compact keys, all easy roles and source replays remain unchanged.

Repair the engine canonical form for an ordered pair of single-character index labels: `a_{i,j}` and `a_{ij}` denote the same indexed symbol. Apply canonicalization only after reading the whole subscript, preserving grouping and base-label equivalence. Do not erase all commas: multidigit coordinates (`a_{1,23}` versus `a_{12,3}`), three indices, empty components, reversed indices, and different bases must not become equal. This conservative rule suffices for every easy shape (indices 1 through 4); it does not guess how to split an ambiguous compact longer index. Native acceptance/rejection regressions will use visible highlights and changed-coordinate controls, with current CLI output before and after shared delivery. Existing source and bank-role regressions remain mandatory.
