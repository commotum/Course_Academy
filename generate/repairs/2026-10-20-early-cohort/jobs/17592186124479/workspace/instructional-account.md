# Pivot-column count generator: targeted repair

The learner inspects leading entries, chooses one or two elementary row replacements, decides whether each residual row vanishes, and counts the remaining pivots. The response is one integer selected from a complete five-option radio bank. Only moderate is supported; easy and hard have no calibrated source evidence here. No diagrams are needed.

Tutorial d45a4eba-96ce-5bef-92b7-b8f0d4cd8b72 says to first convert a general matrix to REF; tutorial feec6418-f447-5ee0-8c62-7d6b690f9228 defines pivots as first nonzero entries of REF rows. Prerequisite topic 149 supplies elementary row replacements and choosing a multiple to eliminate an entry. Source f1ae8763-ab2d-5aee-9b53-3f6da8520aee (q-35457) has two replacements and a vanishing residual, whereas 8a6c1395-93b3-574c-b784-2d33009b00c0 (q-35459) has two replacements and five surviving rows. Source 02683bf4-c015-5b9c-845b-c5f836ec3faf (q-130957) has three rows and two replacements with three surviving pivots. Thus neither dimensions nor operation count fixes the answer.

All 17 captured assessed sources retain original stages, keys, and entire banks via source_replay. Four observed banks are retained separately: 1..5, 0..4, 2..6, and {1,3,4,5,6}. Their distractors are literal alternative counts; no inferred misconception is presented as source fact. The canonical example e-4705 lacks captured answer controls, so only its mathematics can be checked. Source labels remain moderate. No source mathematical error has been demonstrated. Normalized matrix notation and vertically separated operation annotations are presentation repairs already present and retained.

Fixed features have instructional reasons: numeric matrices and a pivot-count query assess elimination rather than symbolic algebra; one or two replacements preserve source workload; five choices preserve the response contract; REF and elementary row equivalence make counting valid; small integer generated coefficients avoid new fraction arithmetic. Original fractional multipliers remain in source replay. Observed shapes and operation counts are kept as source workload profiles. Source arrangements do not justify fixing a surviving row, matrix label, pivot column, or answer position.

The existing normal sampler conservatively extends each source workload: rank varies over supported counts between max(2,rows-2) and rows, limited by its source bank; active row count varies; ordered pivot columns are sampled; nonzero pivots, trailing coefficients, row sources, signed replacement multipliers, matrix labels and choice order vary. At most two residual rows change survival. These preserve exactly the same row-replacement and counting method. Normal extensions use independent prefix rows as elimination sources, while source replay preserves original chained operations. No new solution method is introduced.

Answer-bearing roles are the residual rows surviving elimination and their pivot columns. A zero residual can instead contain a new pivot with all other rows and operations fixed. Coverage must include both outcomes within a shape/workload/bank and, where eligible, within a fixed initial active-row count. Label or nonzero row rescaling must preserve the count. Numeric uniqueness alone is insufficient.

Finding 9fc5bf8959a070427459 is reproduced before editing: seeds 315106964..315106968 delivered ranks (3,3,2,2,4) for row counts (4,4,3,3,5); the strict check fails. Independent random item draws accidentally produced a finite bank solved by rows minus one. Repair batch assembly, leaving generate and source replay available: assemble blocks of two or three items sharing a randomly chosen source workload and active-row count, draw different compatible residual-survival cases in each block, then shuffle the whole batch. An odd final item belongs to a three-item block rather than a singleton workload. This is a coverage obligation, not an equal-frequency quota: two supported outcomes suffice, and three-case blocks include all three when available. All eligible ranks and families remain available across batches. A singleton request has no within-batch contrast guarantee.
