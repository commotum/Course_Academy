# Plot extraction and specification

1. Specific sources. All 39 unique choice assets were composited on white and inspected in eight `q-*-source.png` strips, with the seven available solution plots and guides included. Captured plots contain gray short, centered slope segments in rectangular xy windows; black/gray boundary axes, tick labels, x/y labels, no direction arrows or solution curves. Source domains differ (for example xy uses x≈[-1,3], y≈[-2.5,1], while y−x² and e^(xy) use approximately [-2.5,2.5]²). Worked plots repeat the chosen field, then add blue vertical/horizontal lines: both for possible, one for impossible. Repeated image 43d4b052 is y-only, not both-variable.

2. Generalization. Whole-field dependence is conveyed by whether slopes remain constant as one moves along vertical/horizontal lines. The segment sign, zero location and orientation are meaningful; the gray color, frame and exact tick typography are presentation. No source plot is treated as an arbitrary correct-answer icon.

3. Components. The full source option map appears in template-extraction.md and source-geometry-checks.json. source-geometry.json stores frozen asset SHA256, pixel frame, original dimensions, and independently extracted PCA segment centers/slopes. Correct source equation geometry is checked separately against the actual printed xy, y−x² or e^(xy), with angular error metrics and finite-raster limits. Unknown wrong-field equations are not guessed. Their dependence is independently established by actual segment-angle spreads at fixed columns/rows.

4. Reusable specification. Authored fields use exact SymPy equation data sampled on a 15×15 interior grid in [-2,2]²; Matplotlib renders constant-length centered segments, equal axes, common gray style, common label/tick settings for every option. The solution guide reuses the correct field and adds blue x=.75/y=−.75 lines where needed. Both-variable guides avoid exceptional product zero axes. Changed empirical replay profiles scale complete measured wrong slope clouds and regenerate correct moderate fields from their exact displayed equation; the resulting instance is an explicit empirical-bank reconstruction, not a recovered wrong-operation method. Unit-scale original replay reuses exact original source assets and guide assets. All changed plots are Matplotlib; no direct SVG or image model is used.

Rendering uses the cached Python3.10/Matplotlib fallback because primary .venv lacks Matplotlib. render-provenance.json pins dependency paths/version; render.py asserts the pinned Matplotlib version. No installation or environment edit occurs. Renderer inputs are unique temporary JSON files, and PNG/sidecar outputs use unique temporary names and atomic replacement. Asset names hash exact slope data, bounds, guide role, version and frozen renderer provenance. Concurrent identical and different cold inputs are tested. Sidecars tie every image to the exact instance; check_png.py independently reads actual rendered segment orientations from pixels, including wrong choices.


Changed empirical single-variable plots use robust medians of measured angles within their independently verified invariant bands, on a common 15×15 grid. This suppresses short/clipped PCA fragments that falsely create variation after scaling; it is a documented reconstruction projection, not a source mathematical repair or an inferred exact wrong-field equation. Both-variable measured clouds use observed orientation medoids within grid cells, respecting angle periodicity modulo π; missing cells take the nearest measured cell. Every reconstructed option consequently has the same 15×15 locations and rendering style, preventing density/fragment artifacts from marking the correct option. The full raw measurements remain immutable evidence. Original replay assets remain byte-exact and are copied under images/, with original-assets.json recording SHA256/byte counts for every option and solution/guide asset (plus canonical figures). Normal symbolic fields need no such projection.
