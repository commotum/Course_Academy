# Back-substitution template extraction

The complete source records are retained in source.json/source.edn. Every observed choice is assigned to its own source field, exact vector, complete profile and explicit scale recipe in template-extraction.json. That file gives each source coefficient matrix and RHS, so the source instances remain reproducible.

The fixed backbone is x+a y+b z=c, y+d z=e, z=f, with three nonzero diagonal entries equal to one. Each source has its own names, coefficient pattern and vector notation. The learner selects the entire unique solution in one five-choice radio field named selection. The instructional sequence is: read z=f; substitute it into the second equation to obtain y=e-df; substitute y,z into the first to obtain x=c-ay-bz; conclude with all three coordinates in the source vector notation. No feedback depends on the selected answer.

Two Markdown/value templates preserve angle triples and 3-row column vectors. Prompt scaffolding and source variables are retained exactly; RHS values are substituted in their original slots. The worked solution preserves the shared sentences and operative stages, with explicit subtractions of signed terms. Whitespace, the order of naming y/z before first substitution, and simplified arithmetic grouping are normalized. Fidelity is reported separately from independent mathematical and native grading checks; literal solution replay is not claimed.

The only numerical slot in version 1 is k, an integer in 1..9. It multiplies every original RHS and every coordinate in the *complete selected source bank*. Thus the resulting solution and each observed error vector are multiplied by k. All three RHS slots are coupled deliberately: this is a narrow, exact homothetic generalization, not an independently sampled RHS generator. Coefficients and variable names remain fixed within a profile to avoid inventing bank behavior from sparse evidence. Positive k preserves signs and zero coordinates, existing cancellation, denominator family and the same two substitution steps. Every profile and every k is exhaustively validated.

Each source choice recipe is exactly (k C1, k C2, k C3), where (C1,C2,C3) is its observed mathematical value, with the source constants retained for replay. This is an explicit transformation of a complete observed bank; no pedagogical interpretation of its underlying error is asserted. It changes the source constants together with the system. No recipes are pooled, source choice counts change, or literal distractors copied into a system with independently chosen parameters. This is a conservative supported bank extension. For an invertible source A, A(k v)-k b=k(Av-b), so all wrong choices remain wrong for k>0. The generator still checks every rendered bank and rejects collisions.

This finite version has 99 distinct mathematical systems. Identity includes the normalized system and complete mathematical bank; seed is metadata only. Inventory distinctness ignores seed, identity, option order, variable names and bank. A source or canonical task is excluded even if its displayed format differs. Exceeding the remaining domain yields a bounded capability exception, never copies. There are no eligible target-position slots: every task requests the complete solution of its same three rows.
