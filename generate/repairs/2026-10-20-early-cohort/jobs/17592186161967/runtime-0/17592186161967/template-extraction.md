# Row-zero 3x3 template

The shared purpose is identifying two row additions from supplied before/after matrices, using a nonzero pivot entry to zero the two other entries in its column. Individual source prompts, complete matrices, signs, pivot values, coefficients, layouts, concrete solutions, field IDs, choice values and profile mappings are retained in source-extraction.json. No source choices are pooled across banks.

Fixed backbone: two supplied 3x3 matrices A,B; unchanged pivot row; two requested operations `R_i := R_i + k R_p`; one text radio field `selection`; exactly five operation pairs; solution identifies the pivot, gives the first intermediate matrix and final matrix, then states the pair. Dimensions, number of operations and answer shape stay fixed because changing them changes the workload and field contract.

Slots: pivot row p in {0,1,2}, zeroed column c in {0,1,2}, remaining two rows in ascending order, signed integer matrix A and nonzero integer coefficients k. Compute each coefficient as -A[r,c]/A[p,c] exactly; B[r,:]=A[r,:]+k[r]A[p,:] and B[p,:]=A[p,:]. The operation indices, matrix entries, above/below wording, pivot entry and concluding pair all derive from this single instance. Rows and columns are independent same-method slots. Before/after matrices identify the operations uniquely whenever the pivot row is nonzero.

Observed bounds: pivot values +/-1, +/-2, -3; coefficients from -9 through 4, including unit values, equal/unequal magnitudes, same/opposite signs. A entries range -12 to 12. Source replay retains all original values. Normal sampler: off-column entries [-10,12], pivot {-3,-2,-1,1,2,3}, nonzero coefficients [-9,9], reject target entries exceeding absolute 12. This conservative integer generalization preserves exact divisibility and comparable arithmetic. Reject additional accidentally eliminated columns during normal sampling to keep the solution's designated column unambiguous.

Complete bank recipes are the explicit coefficient-pair arrays in recipes(profile,a,b), not pedagogical labels. Each source choice maps to exactly one recipe index in source-extraction.json. Sign inversions and coefficient swaps are algebraic patterns; unit replacements retain the observed coefficient sign, except q-42531's explicitly opposite unit for its second coefficient. Their psychological interpretation is unasserted. Choose a whole profile before sampling, reject banks with collisions, never take recipes from a pooled list. All profiles retain four distinct incorrect pairs and one correct pair. Interpretation of sparse profiles is limited to these documented algebraic generalizations.

Delimiter-wrapped values are intentional text values, matching the source row-operation prose; mathematical answer types would require delimiter-free values. Answers receive UUIDs owned by their field. Question identity derives from matrices, pivot row and complete profile; seed is metadata. Inventory deduplication ignores profile, seed, whitespace and choice order, so an already assessed matrix transformation is never replenished by an option change alone.

Fidelity: complete operation objects and choice counts compared independent of source order, both captured duplicate banks included; source correct designations checked wherever present. Normalized R braces/spacing and arrow layout are declared display differences. Source solution sentences and three matrix stages are preserved, with parameterized direction and pivot references. No source revisions.
