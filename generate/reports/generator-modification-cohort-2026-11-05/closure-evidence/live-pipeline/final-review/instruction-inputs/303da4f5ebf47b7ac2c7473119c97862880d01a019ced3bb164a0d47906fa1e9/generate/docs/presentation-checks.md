# Mathematical presentation checks

Use the sections relevant to the source and generated representation. These are presentation safeguards under [the principles](../principles.md), not instructions to change the learner task. Inspect unanswered prompts/choices separately from completed solutions.

## Source graphics and mathematical boundaries

When a source SVG title mixes literal TeX with nested MathML, the nested root may represent only an inner fragment. Preserve or reconstruct the complete outer expression, including operators, equalities, labels, fences and explanatory color. If full reconstruction is unsupported, retain the whole graphic or report an explicit extraction gap. Never substitute the first descendant MathML root for the complete formula. Compare source replay against the original complete expression, because truncated math can render with zero MathJax errors.

Treat imported formatting as evidence to normalize, not a template to copy blindly. In prompts, worked solutions, text choices and feedback, delimit every equation with `$...$` or `$$` display delimiters. Use `$$` plus `\begin{aligned}...\end{aligned}` for multirow derivations and preserve `\\` row separators. Never emit bare environments, `[math]` wrappers, indented math/code blocks, or unescaped currency/percentage glyphs. Normalize prose with `scripts/question_capture/math_format.py` before calculating content identities, then validate it; math answer values remain bare TeX. Render through the actual UI and verify that every intended equation and row appears, with no raw TeX outside math containers. Zero MathJax errors alone does not establish successful rendering: an unrecognized block can produce no error at all. For undefined-command QA, run `scripts/check_math_rendering.py` with the local Playwright Python environment. It uses the actual player renderer but disables MathJax’s `noundefined` fallback: that fallback can show a malformed command such as `\intxdx` as red text while reporting no math error. Also check expected equation counts and actual controls; strict syntax success does not prove the displayed content is complete.

## Operators, emphasis and delimiters

Preserve named function/operator nodes as operators: use `\sin`, `\ln`, `\det`, and `\operatorname{arccsc}` rather than bare letters or undefined controls such as `arccscx` or `\arcsecx`. Include inverse hyperbolic functions and powered/subscripted function names. Check upright operator glyphs and argument/power scope in the UI; bare letters can parse without error while displaying the wrong notation. Do not repair arbitrary variable products or literal text by guessing function names.

Size balanced parentheses, brackets and vector angles around complete fraction-containing expressions, including products such as `(5\cdot\frac{\pi}{3})` and valid single-token fractions such as `\frac12`. A rule for a lone fraction is insufficient. Keep script/annotation fractions local, preserve optional macro arguments and deliberate delimiter sizes, and inspect the actual rendered fence height.

Write Markdown emphasis as `**bold**` and `*italic*`, with whitespace outside the delimiters. Never copy padded source HTML as `** bold **` or `* italic *`. Omit empty emphasis wrappers. Check that labels and hints render with emphasis rather than visible stars.
Preserve data-table structure and augmented-matrix partition lines from the source. Use TeX `array` column rules (`|`) and `\hline` for ruled tables; `aligned` is for equation alignment. Check borders, cell alignment, and every cell, since valid TeX can still describe the wrong layout.

## Tables, matrices and systems

For source HTML tables, preserve the source-table HTML contract described in [activity capture](../../capture/docs/3-activity-capture.md): actual cell roles, merged cells, nested tables, alignment, grid rules, and shading. Source replay must use the corrected canonical table layout. Keep existing field keys and answer entity identities when repairing an existing record’s typography. New generated instances need fresh field-owned identities derived from their content. Markdown tables are appropriate for newly authored simple tables with genuine column headers; never infer headers or flatten an imported table into a line of text.

For matrix-entry questions, use `matrix_operands()` and `matrix_answer()` from [math_format.py](../../scripts/question_capture/math_format.py). Put separately wrapping, centered given matrices below the prose. Render the answer as a borderless rectangular matrix with external brackets and the expression outside it. Pass bare TeX for supplied entries and the existing `{{field-key}}` placeholders for editable entries, preserving row and column order. Do not use padded Markdown tables, blank label columns, or spreadsheet grid lines. Radio choices remain their existing matrix answers.

Treat instructional styling as part of the template: retain active matrix rows and columns, pivot and zero-row emphasis, augmented-matrix dividers, vector/basis fonts, visible set braces, and dimension labels. Repeated operand matrices need the source's changing focus, with textual entry or row/column labels so color is not the only cue. Use `\underset{dimensions}{A}` for labels centered below a matrix name; a subscript moves them to the side. Wrap long dot products and split the result onto another line when needed on narrow screens. Check numeric intermediate matrices independently of source fidelity: an original source can contain a sign, operand, or row-operation typo. Keep raw replay evidence separate from documented corrected or authored presentation.

Use `bmatrix`, `pmatrix`, or `vmatrix` for fenced matrices, column vectors, and determinants. A visible initial bracketed label after `\begin{aligned}` needs an empty group (`\begin{aligned}{}[A\mid I]`) or scalable fences: MathJax otherwise silently consumes it as an optional placement argument. Preserve genuine `[t]`, `[b]`, `[c]` placement options. Reserve `aligned` for derivations; a nested determinant inside an aligned derivation still needs `vmatrix`. Normalize the complete formula after its fences are present. Publication checks this in prompts, solutions, math answers, and formulas inside text answers or feedback. Successful MathJax typesetting alone does not verify cell spacing or stretching fences.

Keep augmented and partitioned matrices as `array` when their column rules carry meaning, and size the enclosing fences explicitly: `\left[\begin{array}{cc|cc}...\end{array}\right]`. Plain brackets, parentheses or determinant bars around an array are rejected by publication even when MathJax reports no error. Use `\left\{...\right.` for a one-sided condition-table brace. Preserve explicit author-selected sizes and optional macro arguments. Check actual fence/table geometry as well as syntax; changing an outer alignment or the final inverse does not validate the intermediate arrays.

Apply the same scalable-fence check to systems in `aligned` or `gathered`, including chained implications, and to function parentheses around existing matrices or piecewise definitions, such as `T\left(\begin{bmatrix}...\end{bmatrix}\right)`. A checkbox field key is its rendered option statement and must pass the same validation; blank field keys remain identifiers. Preserve field and answer UUIDs when repairing label typography.

Preserve source table column alignment even without grid rules, and preserve zero-rule fraction stacks. Never copy pipe-and-semicolon table serialization such as `x|=2; y|=3` into a formula; reconstruct the actual aligned rows or data columns from source. Use real `\lim` operators and display standalone limit expressions with `$$`; keep references within prose inline. Piecewise definitions need a visible cases brace and distinct value/condition columns. Absolute-value/cardinality bars, determinant fences, conditional-probability separators, and evaluation bars have different roles: do not infer matrices from pipes across TeX groups, or reinterpret `|x|^3` as an evaluation bar. Publication checks balanced groups, rectangular grids, matrix layout, named limits, and sized-bar delimiters before assigning identities.

Normalize complete matrix expressions before deriving content identities, including outer function parentheses, sums, sets, augmented arrays and one-sided systems. Preserve column rules, all ordered cells and alignment boundaries. A table used as a subscript or teaching label does not require larger scalar parentheses. Use valid TeX delimiter tokens for imported Unicode bars and angles after sizing commands, preserve conditional `\mid` separators, and validate visible checkbox labels as well as prompt, solution, choices and feedback. A zero-error MathJax parse does not establish correct fence height; compare table and fence geometry in the actual player.

Use `matrix_answer()` or `matrix_equation()` for editable matrices and factored inverse answers, and `system_answer()` for editable equation systems. Preserve each source field's actual cell or external prefactor position. Do not build these mathematical layouts as nested data tables or flatten their decorative rows into Markdown tables. Retain source teaching colors and pivot shading after checking that the mathematical cells are unchanged.
