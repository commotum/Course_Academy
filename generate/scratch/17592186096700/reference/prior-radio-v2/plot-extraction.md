# Four-stage plot extraction and rendering specification

1. Every original raster was viewed at full resolution: two practice prompts and canonical prompt. There are no plotted answer options or practice solutions. Each image is297×297, an unlabeled12×12 equal-square grid with five blue arrows, black lowercase labels near their shafts, pale gray grid/frame, no axes/tick labels/origin, no tail dots or background text masks. Heads carry direction; positions do not represent anchored coordinate vectors. Authoritative full widgets were also viewed; their original radio layout agrees with the captured banks.
2. Shared pattern: five translated vectors in one physical square-grid scale; visually recognize signed scalar relations. Grid-relative arrow displacement and head orientation are meaningful. Label position and image hash alone cannot establish the geometry.
3. `original-geometry.json` contains every arrow's tail/tip in grid-square coordinates, each raster's separately fitted gray grid columns/rows, affine pixel transform, PNG hash, actual blue-pixel extent, head-versus-tail width, shaft center error, and recovered grid endpoints. Arbitrary bottom-left grid corner is used as a coordinate convention; it is **not an origin labeled in the source**. All endpoints land at grid intersections, so no unlabelled fractional endpoint needs guessing. The grid fit and bounded pixel errors support exact integer displacement inference. No absent origin/tick label is fabricated.

4. `render_plot.py` uses fixed Matplotlib, equal aspect,30pixels/square, common bounds derived from all five changed arrows plus2square margins, original absent axes/ticks, blue arrows and nearby lowercase math labels. Whole-grid tails/tips derive from the generator's exact vector data. Normal default layouts separate arrows sufficiently for reliable associations. Text's actual rendered bbox is tested against all arrow path shafts/head boundaries and other labels; candidates remain within0.9square of that arrow's local shaft and between35–65% of its length. No background mask hides collisions. Candidate positions are ordered by nearest distance to the shaft midpoint. Actual straight shaft and closed triangle coordinates are tested explicitly, ignoring CLOSEPOLY's non-displayed dummy vertex. A5pixel geometry margin covers a3pixel visible gap plus stroke/antialias allowance; the PNG itself must have no blue pixel within the measured text bbox plus3pixels. Pale grid lines can pass behind text as in the source; there are no axes, markers, or tick text requiring separate clearance.

Every generated asset has a sidecar with exact geometry, physical data→pixel transform, measured label positions/bboxes, actual PNG feature checks, runtime/dependency versions, hashed dependency RECORD files, generator input hash, renderer/lock/runtime hashes and PNG hash. Cache hits require both asset/sidecar and matching provenance/PNG hash. Render inputs and atomic output files are unique; same/different concurrent instances are tested with forced fresh writes. No shared temporary input can mix parameters. Cache files are never pruned during parent QA.

Changed geometry is always rendered. The original image may be reused by raw or completed original cases only when **all** parameters, tails and computed tips match the independently calibrated original raster. The raw original image reference is retained exactly. Raster review/QA separately establishes geometry; hash reuse is not called mathematical verification. Actual generated PNG endpoints and orientation are re-read for validation, then the printed statements and solution are checked against those read displacements. A sidecar alone is insufficient.
