# Template extraction

The backbone is direct inspection of three ordinary integer matrices using two conditions: zero rows at the bottom, then leading columns strictly increasing. The answer contract is three Boolean checkbox fields A/B/C; the prompt polarity determines whether valid or invalid matrices are selected. There are no row operations, reduced-echelon tests, augmented-matrix conventions, or new reasoning stages.

Each source is recorded individually in source.json, the classification table, and source-choice-mapping.json. Every false/true option maps to its original field and original correctness; these literal Boolean banks have no inferred error recipes. The worked solution remains the source definition paragraph, A/B/C inspections, three displayed matrices, and subset conclusion. Exact source replay uses original givens and source layout with two recorded corrections.

Variable slots per source profile: matrix leading columns and zero-row positions, plus integer coefficients. Preserve each observed matrix size, number of nonzero rows, pivot weak-order pattern among nonzero rows, condition-I status, condition-II status, and the original explanatory witness role. For a profile with an interspersed zero row, choose any zero-row placement that still violates condition I; otherwise zeros stay at the bottom. Choose actual leading columns by embedding the observed distinct-column order into the existing column domain. Nonzero pivot coefficients range from -9 through 9 excluding zero; trailing coefficients range from -9 through 9. These are conservative same-method generalizations from the observed signed integer matrices. Original values, including 10 and 12, remain available for replay but are outside the narrower normal sampler.

Changing leading columns changes referenced witness indices together. Moving a zero row changes the ordinal explanation together. A source witness may be a later nonincreasing pivot rather than the first violation: preserve its nonzero-row rank. Keep A/B/C labels, dimensions, polarity, field layout, solution definition style and source-specific conclusion fixed per profile, since they define its response contract and layout. All dimensional and structural domains are enumerated in domain-catalog.json; every declared slot is exercised independently while holding other matrices fixed.

Semantic distinctness depends only on unordered matrix dimensions and leading-column/zero-row sequences plus prompt polarity. Coefficient magnitudes, signs, trailing values, labels, seed, UUID, profile and choice order cannot create a distinct task. Full authored prompt and solution determine stable identities, but identity changes do not count as inventory. Domain products are finite upper bounds; overlap and label permutations can reduce actual distinct capacity.

Normal generation selects a complete source profile before sampling, so fields and solution layouts cannot silently mix profiles. No assets are required.
