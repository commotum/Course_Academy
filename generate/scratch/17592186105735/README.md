`replenish.py` uses the existing EDB integration and application contributor.

existing or deterministic generator identity. It holds the application

and exact-basis readback. It only adds generated content and this KP's generator
reference, checking the receipt for unexpected datoms and source changes.

Complete preparation, generated instances, exact EDN, durable requests,
previews, receipts, readbacks and outcomes are retained under
`reference/replenishment/`. Re-running with a saved request recovers its exact
receipt and verifies that transaction; it does not create duplicate content.
The configured job's `.result` receives the verified JSON outcome.
