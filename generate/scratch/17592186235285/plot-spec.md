# Four-stage plot extraction

1. All14 source prompt plots show blue a, orange b, black c arrows from one grid intersection; no numeric coordinate axes. Their solution plots retain the same vectors and add pale dashed OP=kb, PC=λa, point labels O/P/C, and component labels. The varied directions and magnitudes are substantive. Source grid displacements are read in `validate.py`'s geometries table. The28 plots were inspected in `source-diagrams-0/5/10.png`. Canonical inline raster mathematics was also inspected (`canonical-all.png`, final scalar−1 viewed separately). Tutorial diagrams confirm the same method.
2. Common representation: square lattice with independent vectors; trace a known multiple followed by a parallel but oppositely directed residual. The black c endpoint equals kb−ra. Preserve the prompt versus worked construction distinction.
3. Fixed background white, light gray square grid, blue/orange/black arrows, no coordinate labels. Variable endpoints and bounds derive from exact a,b,k,r. Solution O/P/C point labels use white backing, with dashed path colors and separate mathematical labels. No answer-choice plots occur. Unchanged source assets can be reused only on original parameter replay.
4. `render.py` uses Matplotlib Agg with110dpi and equal aspect. It draws exact-data-derived origin,a,b,C and P; bounds include every endpoint with a two-grid-unit margin. Each asset receives an atomic JSON sidecar recording input vectors, c/p endpoints, bounds and dependency/runtime versions. `render_plots` uses unique temporary input files and private asset directories; both PNG and sidecar must exist for a cache hit. Simultaneous identical/different calls are validated. Assets are preserved, never pruned. Source bitmap raster artifacts/color/font exactness is not claimed for regenerated diagrams; geometric and instructional fidelity is.
