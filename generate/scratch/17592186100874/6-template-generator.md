# Generator and validation

The sibling numeric script exposes `generate(level,seed,template,parameters,profile)`, `generate_easy`, `generate_moderate`, `generate_hard`, and `generate_batch`. Use the repository virtualenv Python. CLI accepts `--difficulty all|easy|moderate|hard --count N --seed N --format json|markdown`. Both seed and count reject bools and other non-builtin-int values; count must be nonnegative. JSON uses the application's field-owned answer UUIDs and delimiter-free math values. Randomness only samples declared slots and shuffles a preselected complete bank.

`observed_raw` requires original parameters and returns the exact source wording/solution/fields and source designations. Missing metadata stays missing. It is evidence-only and ineligible for learning. A normal call at original parameters preserves supplied prose/stages and uses its explicit requested profile. q-49527 completion is authored, with conservative easy placement and mathematically supported fourth source choice. Source originals have different UUIDs from all authored/generated records.

`validate.py` is root-independent and uses the private frozen printed-LaTeX parser. It reads actual displayed integrands, substitutions, derivative/differential relations, both rows of the bounds table, both integrals of the change-of-variable equation, every final equality, the actual primitive's derivative, and separately signed endpoint components before collecting the answer. SymPy's positive-u branch comparison is applied only to radical identities after the nonnegative-interval checks. Endpoint errors cannot disappear merely by canceling in a final difference.

The validator replays every original complete bank mathematically one-to-one against independently derived recipes, preserving correct designations. It checks original raw prose separately from mathematics. It exercises every source family at changed parameters plus explicit boundaries, detects profile collisions rather than pruning options, tests deterministic batches, validates UUID/content/task fingerprints, rejects malformed API types and runs both CLI formats from /tmp. `boundaries.json`, `validation-report.json`, `recipe-audit.json`, `side-by-side.md`, `engine-input.json` and `engine-report.json` preserve reviewable evidence.

The frozen `check-engine` and matching Rust source use the existing `course_academy_engine::learning::grade_field` interface with an in-memory snapshot. There are no EDB connections or engine edits. Every radio option and canonical/unreduced-equivalent/wrong blank submission is exercised. The raw unrated original cannot be graded because its correct lookup is absent; its separate authored completion is graded.

Content identity hashes actual prompt, solution, field contract, complete bank and answer; seed is excluded. Mathematical task identity includes actual integrand, both original endpoints and operation. Different banks cannot collide under one generated question UUID; metadata records repeated task identities separately from content identities. Scope and limitations are explicit in the validation report.
