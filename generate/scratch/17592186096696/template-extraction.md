## 2. Shared patterns

Isolate a first derivative equal to a function of the independent variable, integrate once, include an arbitrary additive constant. Every choice is a complete equation, not a bare primitive fragment. The unrated no-C distractor is retained only in raw evidence. Normal generated choices all contain a full arbitrary-constant family. Exact primitive components are kept separately until the last collection row. No distractor feedback is invented.

## 3. Component and bank mapping

Every original choice remains attached to its original source profile; its exact expression and source IDs are retained in source.json and printed in review.md. Parameterized evidence mapping is uniform and fully specified: replace the complete dependent function f(x) or y and every complete derivative component by k times that component, leaving each original RHS expression and C unchanged. Thus k f′=g has family k f=F+C; changing k changes the required slope/primitive to F/k while carrying the entire observed bank. The original corresponds to k=1. Full component masks protect commands and independent variables; nonunit k uses grouped visible multiplication so −5 followed by 2 cannot print −52. This is a defensible algebraic transformation of every whole bank, not an inference of any opaque distractor's pedagogical intent. No polynomial fit or sampled source-answer lookup is used. Profiles remain evidence_only=true and eligible_for_learning=false.

Source values in their original order, together with the transformed values at k=2, are in review.json; every source value is mapped one-to-one, 40/40. Correct designations match 7/7 present; the eighth is absent. Mathematical family comparison permits C→aC+b, a≠0, while requiring the C coefficient to be independent of x. Normal banks reject an entire instance whenever two full families are equivalent or a wrong family also solves the ODE.

The normal authored bank is computed from displayed forcing components g_i and actual individually evaluated primitives P_i. Its operations, chosen together before parameter sampling, are: correct ΣP_i/d; reverse signs −ΣP_i/d; retain the derivative components Σg_i/d; multiply by the power/inner factor instead of dividing (P_i times factor squared, since P_i already contains division); omit the last primitive (or omit outer coefficient for one-component questions). For a reciprocal-linear primitive, the fourth operation inverts the outer coefficient, P_i/a_i². These are explicit authored operations, not claimed source-error reconstructions. All five choices include +C, independent of selected error. Equivalent/invalid banks are rejected wholesale; there is no first-valid distractor pool.

## 4. Reusable rendering and constraints

Observed rendering uses complete derivative/dependent-function masks in the original Markdown, preserving all source field layouts, full bank and worked-solution sequence. Original missing attributes stay absent in the public generate API and CLI. Dependent scaling is a nonzero rational with magnitude ≤8 and denominator ≤4. Parameters are validated, never silently repaired.

Normal rendering uses the source's common isolation and integration prose, then formal integration, distribution, an ordered individually evaluated primitive-component row, and final collection. When the derivative coefficient is one, the prompt is already isolated and the opening is q-119032/q-119034's “First, notice that the derivative term is already isolated on the left:”; nonunit coefficients retain the rearrangement opening. This is explicitly an authored normal template rather than a claim of exact observed sequence for every family. Primitives use ordinary sin/cos/exponential and ln with absolute values, without CAS hyperbolic rewrites. Poles restrict solutions to connected intervals; domain metadata is outside learner content.

Each template has a fixed component grammar and workload, specified in classification.md and enforced by guard(). Hard adds three equal-workload authored templates within the same integration rules. Family fingerprints depend on the canonical forcing g/d; aliases, seed, order and banks do not alter assessed task identity. Content identities include actual prompt, full fixed solution, bank, layout, rating/key presence and version; shuffling alone cannot change them.

No plot extraction or generation is required (steps 5 and 7: none). No registration or database transaction is performed.
