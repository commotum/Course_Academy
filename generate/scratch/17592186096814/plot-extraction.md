1. All six original PNGs (three practice prompts, hard solution, canonical prompt and canonical solution) were inspected at their original full resolution via view_image. All black labels and directions were explicitly inspected, including both sum arrows and the hard red resultant.

2. Shared visual pattern: square pale grid, blue length1 marker spanning two subdivisions, black vector arrow(s), adjacent italic labels. Sum plots identify start A and final B. Worked diagrams add red resultant, right-triangle dashed legs and A/H/B labels; no coordinate components are printed in learner prose.

3. Geometry uses A=(0,0), P=a for sums, B=a+b (single B=a), H=(Bx,Ay). Each arrow uses its own tail/tip and label; no renderer sampling. The source full-resolution raster can be reused only at the exact original replay parameters. Changed geometry is rendered from the same question instance using Matplotlib. No SVG generation or image models. Renderer inputs/outputs and plot roles are deterministic. Axis bounds expand by at least1.5 units around every point; equal aspect, half-unit grid; labels offset normal to arrows. Original pixel styling is incidental; scale, geometry, labels, head-to-tail order and arrow direction are instructional.

4. render_plots(instance) derives both prompt and solution assets and exact geometry sidecar from the question's parameters. Unique temporary input filenames and atomic PNG/sidecar replacement allow simultaneous identical/different calls. Cache hits require both PNGs and sidecar. Matplotlib's existing cached Python3.10 fallback is used read-only because primary Python3.13 lacks it. Renderer version and Python version are recorded per asset. Concurrent fresh renders are tested in the private concurrency directory. Source-path-only fidelity is not used to establish changed geometry: independent tests reconstruct vector lengths/directions from the exact rendered sidecar and actual printed choice/solution mathematics; rendered variants receive manual visual QA.

Final visual QA inspected the regenerated source geometries, two examples of each authored level, and fresh concurrent same/different-instance prompt/solution renders. Signed vertex labels use direction-dependent offsets. Red resultant labels choose a clear location among six offsets using distance from both black segments, dashed guides and black vector-label anchors; this repairs the observed changed-parameter collision between n and m+n. Final reviewed hard examples place these labels visibly apart. All bounds, unit markers, half-grid increments, endpoints, arrowheads and solution-triangle directions were legible; no clipped labels found.
