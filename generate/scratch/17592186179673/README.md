# Local circle/ellipse generator

Run `.venv/bin/python generate/scratch/17592186179673/validate.py` from the repository root. CLI example: `.venv/bin/python generate/scratch/17592186179673.py --difficulty all --seed 4 --count 2 --format json`.

API: `generate(level, seed=0, template=None, field_type=None, parameters=None, profile=None)` and `generate_easy`, `generate_moderate`, `generate_hard`. Normal templates are `authored_easy`, `authored_moderate`, `authored_hard`, with profile `authored_operations`. Explicit authored parameters require integer a,b,m,n,h,j,k within classification bounds. Source templates are the eleven original q IDs, profile `observed_<q-id>`, parameters `{ "c": 1 }` for exact replay or another nonzero integer multiplier with |c|≤5. These profiles use scalar linearity for every complete observed mathematical component; unexplained distractor intent is not claimed as recovered and the profiles are not normal default banks.

Source fidelity compares all raw problem/full worked-solution strings, all 55 whole answer values, types/layout and all 11 correct designations. Independent checks parse the actual displayed one-form, curve, endpoints, tangent equations, limits, all arithmetic stages and choices. Native checks use the real `learning::grade_field` through `generate/runs/current/check-engine`; field-owned IDs are checked for all five options. Radio grading is kept separate from mathematics. Original endpoint-singularity qualifications and the authored missing hard scope are in classification/extraction, not hidden as perfect ordinary-integral source statements.

Content identities include version, actual problem, ordered fixed solution, entire unordered bank, designation, assessed task and domain; option order/seed and unused easy h cannot change identity. Task fingerprints include P,Q,axes, assessment shape and integral limits, because setup options assess those limits too; profiles/banks stay out of task fingerprints. The unused easy h remains generation metadata only. Full source records retain raw evidence and snapshot provenance.

No database writes, registration, engine edits or transactions. Only this generator and its evidence directory are changed. `review.md` / `review.json` contain each observed bank's changed-parameter replay and two clearly authored examples at every level.
