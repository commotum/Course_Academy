# Four-stage plot extraction and specification

1. Every original plot appears in `extraction.json`, including its role, source reference, dimensions, SHA256, panel origin fitted from actual axis ink, blue extents and full panel descriptions. Full-resolution inspection covered all 11 original prompt sets and all 7 solution sets. No original option is a plot. Source features include finite frame-truncated curves, curve/line joins, isolated filled dots, disconnected branches and a hollow endpoint. No curve carries an arrow; positive axis directions do. The axes are unnumbered and have no grid, so no symbolic coordinate scale is claimed.
2. The shared plot pattern is four coordinate-plane panels I–IV, blue function curves and black axes. A worked diagram adds dashed horizontal lines and sometimes intersection dots. Both passing and failing panels need to retain their entire visible domains. Full-scale raw reconstruction is a separate check of extracted ink geometry, not a substituted exact-function assertion.
3. Raw component data are complete composited ink pixel coordinates and RGB colors, with source white/transparent background normalized for inspection. Every pixel, including hollow marker boundaries, undergoes the same positive affine map about the raster center. The raw recipe is public and parameterized; the smooth mathematical formula remains unresolved. Original image paths are retained at scale 1, with private copies and independently rendered reconstruction previews.
4. The eligible Matplotlib specification is a 1080×960 white four-panel figure, equal x/y scale, bounds −4.7 to 4.7, labelled positive-axis arrows, panel labels outside all curves, and two-point finite endpoint markers. Easy has familiar complete finite curves. Moderate/hard draw exact straight/quadratic segments; faint horizontal ordinate guides and numeric labels tie equal endpoint levels across pieces. Open circles exclude endpoints. Black dashed solution lines come from an actual analytically derived failing-level witness; passing panels show an illustrative line. The complete mathematical proof is the horizontal-line criterion over all ordinate cells, not one illustrative line.

All geometry and solution witnesses are supplied by the same question instance; the renderer does not sample. Actual text bounding boxes are measured after canvas draw against sampled curve/axis paths and canvas bounds. Endpoint markers are read back from the actual PNG for filled versus hollow centers. Exact curve points are checked against decoded blue PNG pixels under the actual axes transform. Sidecars record Python/Matplotlib versions, exact functions, axes pixel boxes, text boxes, bounds, hash and dimensions. There are no white label masks. Endpoint marker sizes have space from the figure boundary; horizontal guides retain coordinate association without crowding curve tips.

Rendering uses unique private temporary inputs, atomic final PNG/sidecar writes and a cache requiring both assets and valid PNG hashes. Fresh concurrent same/different geometries are validated without pruning active caches. Raw plots have no numeric calibration because the source supplies none; normal plots have declared finite domains and explicit markers, so no unseen asymptotic or global continuation is inferred.
