# Plot extraction and specification

All fourteen prompt and solution diagrams were inspected in `source-contact.png`, with individual full-resolution inspection of the ambiguous scales. Original PNGs are copied unchanged under `originals/`. Source prompt diagrams show a square grid, blue a, gold b and black c from a common origin. Easy mostly uses horizontal a and vertical b, with integer, half, or third target ratios. Moderate uses oblique b (and one oblique a), requiring a translated known multiple. Worked diagrams add O, C, A/B or P labels and colored dashed path components. Direction arrowheads on a, b and c matter; guide paths need not introduce additional arrows. No plotted answer choices exist.

For source replay only, unchanged source plots are reused when **all** basis coordinates, coefficients and unknown roles match. Changed parameters produce Matplotlib unit-square grids with the same color roles, origin and endpoint labels, and dashed known/remaining solution paths. Drawn C is ca·a+cb·b, P is the known component endpoint. The solution labels its components with exact scalar multiples. Prompt plots contain the three original vectors, without supplied scalar labels. Hard exact point coordinates are printed below the plot because fractional grid coordinates otherwise become unreliable visual estimates. Bounds include every basis endpoint, C and P plus margins. Labels are offset from arrowheads.

The primary .venv has no Matplotlib; `render.py` invokes the already-cached Python 3.10 runtime and cached package wheels read-only. It installs/downloads nothing. Each render call uses a unique private JSON input, then atomic PNG and sidecar writes. Cache hits require **both** PNG and sidecar. Inputs are cleaned independently. Concurrent identical/different requests are tested. Sidecars include the exact coefficients, input geometry, display endpoint transforms and renderer versions. All earlier assets are preserved through parent review; no pruning is performed.
