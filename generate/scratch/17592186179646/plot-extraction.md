# Plot specification and visual review

source-plots.png contains every prompt/solution asset from all eleven practice sources and canonical e-15149. Source refs and placement are preserved in source.json. Prompts use a square centered on crossing x/y axes, blue outline and gray arrow field: parallel arrows for uniform fields, inward/outward radial arrows for negative/positive radial fields. Arrow lengths convey field behavior; no quantitative flux is inferred from arbitrary rendering scale. Solutions remove the field, label C1 right, C2 top, C3 left and C4 bottom in blue, label signed half-length coordinates, and show four orange outward normals. Some source normal subscripts differ on unused sides; new plots consistently use the documented side pairing.

There are two ordered assets per complete question: prompt vector field, then solution outward-normal diagram. No choice images occur. The incomplete source has only its prompt. Its inferred solution reuses the unchanged same-size source solution diagram; original evidence is retained. Source replay reuses unchanged original bytes; parameter variants need new plots because coordinates, field direction and scale change.

render_plots(instance, output_dir) uses Matplotlib only, with equal aspect, explicit coordinate limits and deterministic PNG names. L controls square coordinates and limits; c and axis control arrows. All sides, normal vectors, labels and coordinate marks are derived from that same instance. No independent sampling occurs inside plotting. Each normal points outward. The renderer uses 4 by 4 inch figures at 130 dpi; margins retain labels and arrowheads. No direct SVG rendering is used.

Generated positive vertical/horizontal uniform and outward radial examples were inspected side by side with originals in generated-plots.png. Labels, coordinates, crossing axes, outline, side relationships and normals are legible with no clipping. Signed negative generated examples are included in review.json and also reviewed before commit. Content-addressed publishing uses the existing ImageLibrary; exact bytes and SHA-256 references are checked on write and readback.
