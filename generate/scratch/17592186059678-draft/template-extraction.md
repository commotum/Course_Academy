# Backbone before variation

The supplied object is a real scalar function y of x. The target is the second derivative in Leibniz notation. The learner first differentiates the supplied function, then differentiates that result. The lesson explicitly introduces this two-step computation; trigonometric and logarithmic differentiation are prerequisites. Derivative order and the y/x roles are fixed by this KP; changing the order or introducing an evaluation point would change the task.

Each source profile preserves its expression tree, number-form/sign pattern, field key/type/count, entire bank, and the exact ordered worked-solution stages. Most profiles show: derivative of the supplied expression; optional rewrite of radicals/quotients as powers inside that operator; power/trigonometric/logarithmic rule arithmetic; simplified first derivative; derivative of that exact first derivative; rule arithmetic; optional negative-power simplification; final expression. The source-specific sequence, including zero terms and unequal row counts, is recorded completely in `component-masks.json` and checked on every served instance. Shared sentences are retained. Nothing is replaced by a generic two-row solution.

`component-masks.json` is the extraction: each full source prompt, worked solution, and every answer has explicit, ordered character spans, raw mathematical components, and a coefficient-slot index. The multipliers scale independently the same original input summands and their dependent first/second derivatives. A multiplier of one produces the exact source text before narrow typography normalization. Other values retain each original rule-application term, applying its constant multiplier; no stage is removed or added. This is an authored constant-multiple generalization, not evidence of other observed parameter combinations. All signs and source exponents stay fixed.

Easy uses positive integer multipliers 1..6. Moderate uses 1..10. The hard calibration uses positive odd-half multipliers 1/2..19/2 on the non-linear terms of q-342868. Linear-term multipliers in q-342868/q-342877 remain one as an explicitly narrower policy. Source parameters are all multipliers equal to one. Independently changing a coefficient gives a new supplied function and corresponding bank, not a renamed or reordered option. Capacity hashes the full symbolic supplied function and the target fragment, not seed, profile aliases, or option order.

The four radio profiles preserve every observed option, in its observed bank, via its component mask. All 16 distractors are mapped without inferring a psychological mistake. For example q-10903 retains both 60x²+8x and 60x³+8 as distinct observed wrong structures. q-104192 retains its reciprocal-radical, positive-radical and trigonometric-sign patterns. q-104191 retains its reversed term order and altered denominators. The validator independently re-derives each whole bank algebraically from coefficient slots; correct keys are field-owned.

q-342970 expects only the polynomial and trigonometric part: the printed rational suffix completes the second derivative. The suffix varies with the third coefficient everywhere, including the worked solution; entering the full derivative into the fragment is wrong. This field contract is retained.

Domain: x>0 for logarithmic/radical profiles; x!=0 for rational-only profiles; otherwise real x. No real-domain branch inference is made from positive simplification without declaring this domain. The only served repairs are typography: remove invisible function-application characters and convert bare ln/sin/cos tokens to TeX commands; raw Pull data remains exact. Incomplete source records remain raw-only; no missing field layout, solution, difficulty, or key is invented.
