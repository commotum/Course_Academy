# Plot extraction and reusable specification

1. Original specific plots:12 practice PNGs with transparent background. Prompt arrows are black, single choices orange, and paired choices blue/orange. Source drawings have no axes, ticks or grids. Bold/italic math labels lie near the arrow midpoints. Each source uses a common physical pixel scale across its prompt and options, although individual image extents differ. For q-11324 the base length is about99 pixels; q-12140 about198 pixels. Captured pair labels remain3a/−a even in the wrong-length/direction options. Exact path values and original dimensions are preserved. White-background copies live in originals/ for full-resolution review; source files themselves remain unchanged.

2. Shared pattern: straight arrows with explicit directed tips and nearby vector labels. Required mathematical content is orientation and relative length, including reversals. Position/translation, margin and typography are incidental. This is heavy plotting because prompt and all five options carry the assessed data.

3. Components: nonzero exact scalar multiples of a=L(cosθ,sinθ); arrow tails chosen for clear translated placement; tips tail+vector; correct full bank selected before rendering; requested labels on all options; consistent black/blue/orange colors. No coordinate-reading demand is introduced. Every original bank's arrow tails and tips, with actual raster stroke/head checks, are recorded in source-raster-checks.json. Canonical prompt and both solution diagrams were inspected separately.

4. Supported presentation repair: Matplotlib writes **180 × 180** white PNGs with a common equal-scale viewport for the prompt and the entire bank. The original registered600px canvases were displayed at different sizes by `.prose img {max-height:480px}` and `.choice img {max-height:200px}`. A180px image plus the player's16px border fits both caps without rescaling. This renderer revision changes affected presentation assets and identities, retaining the original scalar-multiple tasks, complete banks and prose. The raw original MA rasters and prior approved/generated inventory records remain exact evidence; source replay is separate from this served presentation repair.

Arrow line widths and head sizes are chosen for the compact actual display. Actual patch path vertices, directed tips/tails, raster stroke/head support, labels, bounds, real text boxes and renderer versions are recorded in sidecars. A deterministic label-position search tries perpendicular placements and small along-arrow shifts, rejecting any position that clips, touches any arrow, or overlaps an earlier label. It changes only incidental text placement. No masks, axes or coordinate-reading demands are added. Rendering uses one shared viewport across prompt and every option, derived from the whole selected bank; no per-option autoscale is permitted.

Validation covers the full finite normal domain, including all six orientations, both common base lengths, three positive scales, four negative rational scales and all12 requested scale pairs. Pixel tests read the actual rendered arrow path and PNG ink, not just intended coordinates. Browser QA uses the current player's actual Markdown, DOMPurify, MathJax, image radio controls and CSS. Its normal repaired records must show identical natural and displayed pixel sizes for the prompt and all five choices. Raw historical source/canonical images and legacy existing inventory are rendered as evidence; their original display limitations are documented rather than silently rewritten in the capture.

Original raw images are reused only for exact source replay. New normal practice always uses owned compact Matplotlib PNGs. No SVG renderer or image generation model is used.
