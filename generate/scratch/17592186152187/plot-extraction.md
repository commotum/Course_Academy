1. The captured Introduction plot was also opened at full resolution: an integer grid shows horizontal radius 4 and vertical radius 3. Every original was opened at its full native resolution (360×304 pixels), including all 13 practice plots and canonical e-6814. Each has white background, black x/y axes with positive arrowheads and x/y labels, a thin blue full ellipse centered on the crossing, and signed endpoint coordinate labels. Actual plot orientation was read independently: q-15803 (3,5), q-15856 (7,2), q-106392 (8,3), q-106393 (5,3), q-106394 (2,6), q-106701 (7,4), q-274855 (6,4), q-326267 (2,9), q-6889 (3,4), q-79284 (8,5), q-106391 (3,6), q-6880 (4,2), q-79281 (2,4); canonical (3,1). The x/y positive and negative signs are clear in every raster. Traversal plots mark the rightmost point in black and label A(a,0), except q-326267 J(a,0); they have a blue tangent arrow on the upper-right arc directed upward/leftward, confirming counterclockwise. Graph-only plots have no such marked point or traversal arrow. There are no plotted answer options.

2. Shared pattern: use an equal-unit coordinate plane to display the oriented semiaxes. The graph supplies the radii in easy; the traversal illustration shows the initial point and orientation in moderate. The canonical's a=3,b=1 supports the same formula with a unit coefficient.

3. Components: axes crossing at O=(0,0); ellipse vertices (±a,0),(0,±b); labels ±a and ±b; optional marker at (a,0), optional coordinate label and tangent arrow. All actual radius values and points derive from the same exact question instance. Source images are separately preserved under `originals/`, with `original-plot-spec.json` mapping every asset and inspected mathematical contents. Source plots are not assumed to have a single common coordinate scale: tall and wide figures were individually read using their own endpoints and signed labels.

4. Reusable specification: `render.py` draws via Matplotlib only, with equal aspect, white background, black axes/arrowheads and blue ellipse. Bounds depend on max(a,b). Normal easy/moderate display signed endpoint values; hard displays a faint half-unit grid with even integers labeled on fixed grid margins, leaves endpoint values unstated, and labels only the marked point letter. No transparent white text patch hides a mathematical feature. The actual text bounding boxes are measured after drawing and moved outward until they clear axes, the sampled ellipse path and already placed labels. Boxes must lie within the panel. Hard numeric labels remain at their exact corresponding coordinate on the grid margins, so no outward move disconnects a value from its tick coordinate. The marker is on the horizontal axis, so the axis-clearance condition also prevents label/marker coverage. There are no mathematical shifts or unmatched plotted fragments.

PNG and sidecar cache keys contain the versioned renderer and complete meaningful diagram parameters. Every render-input file is unique; PNG and sidecar writes are atomic. Cache reuse requires both files. The sidecar records actual Python/Matplotlib/NumPy versions, axis transform, radius pixel extents and actual text boxes. QA independently reads actual blue pixels from each PNG and compares all four extents with transformed radii within 4 pixels for stroke/antialias allowance. Fresh concurrent identical and different parameter calls are checked. This bounded pixel test handles thin ellipses without imposing an arbitrary aspect-ratio tolerance.
