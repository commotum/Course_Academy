# Template extraction

Read `classification.md`, `source.json`, and `source-choice-mapping.json` for every observed matrix, source UUID, choice value, exact index-set recipe, and correct designation. Each profile is one complete original five-option bank. The recipe is concrete: replace the listed cells by zero, with a shared old-column-to-new-column map applied to every cell in every bank. No distractors are pooled or inferred from a named misconception. Their pedagogical interpretations remain unresolved where the source provides none.

Shared pattern: recognize which proposed entry removals make a matrix satisfy row echelon conditions. Supply matrix A; request one complete set of cells. Keep a single five-option radio field named selection and text labels ending “only”. Correct sets contain two or three nonzero entries. Keep the source solution sequence: “Notice that by replacing [cells] with 0, we get a matrix in row echelon form:”, original matrix → corrected matrix, then “The other options will not give us a matrix in row echelon form.” All references derive from the same concrete parameters. The solution is independent of the learner selection.

Fixed: 4x4 dimensions (comparable source workload), requested zero replacement operation, source bank membership, radio contract, two or three actual removals, solution stages and sole correct option. Variable: each source profile, nonzero signed integer entries, and a shared column map determining every supplied cell and every queried target. Row order remains fixed to preserve the top-to-bottom echelon check. Column movement is a generator sampling operation; learners still only choose removals, not a column operation. Rows containing only zeros must remain below nonzero rows in the correct result.

Observed parameters: exact signed matrices and identity column maps in `source.json`. Normal sampling: magnitudes/signs in {-9,...,-1,1,...,9}, source zero support, and permutations of four columns applied simultaneously to matrix and complete bank. This column-slot extension is authored, conservative same-method variation, not observed source evidence. Accept a map only when every selected cell of the source correct set is nonzero, the original matrix is not echelon, and exactly the source correct option produces echelon form. The new target slots retain the role “entries to replace by zero”; pivot and zero-row relations are checked rather than tied to original locations. Rejected maps are recorded in `slot-coverage.json`.

The public sampler uses the finite catalog; explicit parameter input supports source replay and controlled validator cases. All 24 maps per profile are independently tested. `changed-target.json` holds the mathematical matrix fixed while changing target slots and independently reads the prompt, solution and key. Numeric signs/magnitudes have no grading significance; they never create fresh tasks. Freshness uses original leading columns, the correct removed set, and corrected leading columns. It ignores numeric entries, distractors, seed, UUID, order, and profile. Stable authored UUIDs include the complete normalized content so two different authored banks cannot share one identity; the stronger freshness fingerprint prevents duplicates across those identities.
