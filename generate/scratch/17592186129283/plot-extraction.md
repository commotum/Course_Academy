1. The 29 source region plots are black horizontal u/vertical v axes with arrowheads, no ticks/grid, a dashed blue strict boundary, pale blue shaded region and a TeX boundary label. Line slopes include ±1,1/2,1/3,2; parabola coefficients include ±1,±2; cubic coefficient1; hyperbola coefficients include1,-1,-1/2,1/3. 2. The plot set communicates a strict sign region, not a transformed output object. Same-side hyperbola distractors and correct opposite-branch product regions must remain distinct. The coordinate axes are references, not implicit zero-J boundaries.
3. Geometry components are degree n, rational c, offsets h,k and complete shading predicate. For n≥1 the boundary is v=k+c(u-h)^n; for n=-1 it is v=k+c/(u-h), with each branch rendered separately. Product predicates use (u-h)(v-k)>c or <c; global above/below predicates explicitly preserve wrong same-side branch plots. For easy, vertical boundary u=h with left/right shading or horizontal boundary v=k with top/bottom shading. Source coefficient/degree/mode values are independently recorded in extraction.json; labels are generated from these same complete objects.
4. `render_plots` accepts computed specs and returns paths for prompt/choice/solution placement; normal questions need five choice plots and reuse the correct one in the worked solution. Original exact geometry profiles may reuse unchanged source assets. Changed geometry uses Matplotlib Agg only, with one common set of axes/bounds per complete bank, derived from all translations and characteristic coefficient scales. Actual PNG shading is probed independently and the renderer boundary label is parsed against the plotted equation. Source crops differ but all normalized variants share presentation. Black arrows, dashed boundaries and pale blue regions are preserved. Figures use equal aspect, readable labels on white boxes away from the curve, no misleading ticks; hyperbola discontinuities never join. Primary venv lacks Matplotlib; render.py delegates to cached Python3.10 wheels, without installation/shared environment writes. Versions/dependency paths are in render-provenance.json. No image model, direct SVG or DB operation is used.
