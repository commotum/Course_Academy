# Plot extraction and rendering specification

Stage 1, every original: plot-extraction.json binds each full-resolution raster by SHA256 and dimensions, including canonical e-1222 and all seven practice originals. White background; black horizontal and vertical axes with positive-end arrows; increasing blue exponential curve; blue filled y-intercept marker with (0,u) label; dashed black horizontal asymptote with y=c label. There are no grid lines, numerical axis ticks or curve arrows. Source labels: canonical c=4,u=6; q-18518 c=-2,u=0; q-18521 c=-1,u=2; q-29233 c=-2,u=1; q-7239 c=-1,u=2; q-7241 c=4,u=5.5; q-7243 c=2,u=5; q-99778 c=-2,u=1.

Stage 2: the supplied base and graph annotations determine c, then k=u-c. Preserve the left tail approaching c from above and positive increasing curve, independent of incidental axis aspect. Original plots have uncalibrated x scale, so recovering b from numerical shape would be unsupported. Vertical scale ratios are approximate without grid calibration. Labels establish coordinate values; evidence does not claim exact source pixel-to-coordinate metric recovery.

Stage 3: background; two axes and arrows; b,k,c; labeled/marked u=k+c; dashed line y=c; variable viewport showing origin, asymptote and intercept with margins; blue curve sampled from exact instance. Fixed blue/black roles and uncluttered labels. No arrow is added to a curve whose source has none. Only one prompt plot per variant; answer options are equations/pairs.

Stage 4: Matplotlib renderer uses the same b,k,c and step as the question. Easy/moderate reproduce annotated source visual roles, signed labels and decimals. Authored hard adds light horizontal calibrated grid and signed half/quarter tick labels, suppresses labels at the assessed intercept/asymptote, and retains the marked intercept. It requires reading two coordinates; the worked solution explicitly says the grid was read. Viewport derives from c,u and the curve's positive range. Source replay at original parameters reuses exact copied original image. Changed source replay renders anew.

Each render uses a unique input file; PNG and both JSON sidecars are atomically replaced under a versioned parameter hash. Cache hits require PNG, renderer sidecar and raster-readback sidecar. Sidecars record actual Python/Matplotlib/NumPy versions and cache dependency paths. PNG blue pixels near x=0 independently verify the marker; dark left-side rows verify the dashed asymptote; sampled transformed curve points must fall on actual blue raster strokes. Readback hashes bind the actual displayed PNG to these checks. Actual label strings/tick values are recorded from the renderer; full-resolution human image review checks sign, fractions, legibility and placement. No automated OCR claim is made. Fresh same/different concurrent renders exercise isolation.

Raster channels are converted to signed integers before comparisons so white-channel uint8 overflow cannot be mistaken for blue. Source transparency is composited on white for numeric inspection. Accepted cache version is v5; retained v1–v4 QA is superseded. Feature and axis-name labels use their actual Matplotlib mathtext bounding boxes to select the nearest clear candidate, with clearance from axes, asymptote, curve stroke, marker and other text. No backgrounds hide features. Hard ticks remain centered on exact numerical y coordinates; a regular named stride is derived from measured fractional text height and vertical scale, then collision/boundary labels are suppressed. Four-pixel actual-raster clearance is independently checked. Named labels remain calibrated to the true grid; no tick is detached.

Visual review: labeled negative integer example and negative half-integer intercept are clear; positive-grid hard examples at step=1/4 and step=1/2 show readable signed ticks, the suppressed marked-point value and dashed level are recoverable. Full review samples include all source profiles and both authored banks at every level. No direct SVG or image-model output is used.
