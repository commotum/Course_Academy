# Template extraction

## 1. Specific originals

The individual forms, coefficient properties, exact evaluation angles, field keys, and step sequences are listed in classification.md; the complete original Markdown and every original option are retained in source.json. All coefficients are positive integers except the explicit leading minus sign. No branch or domain approximation is used.

## 2. Shared instructional pattern

Differentiate a linear combination containing tan x by linearity and d(tan x)/dx=sec²x. Return either the full derivative expression (easy) or its exact value at an observed regular angle (moderate). The extracted layouts remain separate where notation, field response, or worked sequence differs.

## 3. Components and complete banks

source-choice-mapping.json maps every original choice, field, exact printed value, generated value at observed parameters, and recipe. Recipes are observed expression patterns; error intent remains unresolved where the source gives no diagnosis. Blanks have no distractors. Each radio uses its entire source profile; no pooled or mixed bank is formed.

## 4. Reusable templates and constraints

The Python replacements match complete mathematical expressions or complete worked rows. Numeric field values have a separate renderer; no global replacement of single digits is used. Shared prose, variable names, placeholders, field keys, solution row order, evaluation points and trigonometric identities are fixed. Coefficients are variable and calculations are tied to the same parameters. Values a,b,c are integers 1..6; explicit out-of-range parameters are rejected. q-70911 rejects a=1 because two source recipes coincide.

Domain: radical questions require x>0, and all tangent derivative expressions exclude cos x=0. Moderate evaluation points 0, π/4 and π are regular. No plots or optional components. All seven complete original profiles replay through the same parameterized rendering path without a literal-source bypass.

For distinct-task counting, derivative questions ignore additive constants, and equivalent functions/layouts share a fingerprint. Presentation identities retain the fixed rendered prompt, solution, profile, version, and parameters. Seeds and answer ordering never establish a distinct task.
