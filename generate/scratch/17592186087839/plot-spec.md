# Plot extraction and rendering

1. Original plots were inspected at full resolution individually, plus source-contact.png. Each is a black Cartesian axis pair with positive-direction arrowheads, x and y labels, no grid, a continuous thin blue closed ellipse, and four intercept ticks with numeric labels. All are centered at (0,0). There are no plot choices or solution plots. `source-plot-audit.json` records every practice PNG's original size, hash, blue extent and separately calibrated pixels per horizontal/vertical unit. The canonical raster (5,3) was inspected too. Every intercept and sign agrees with its solution; no fractional coordinate is unlabeled or inferred solely from pixel shape.

2. Shared plot pattern: read the positive intercept labels as a,b. Source images are not uniformly equal-scale: for example q-69890 visually appears nearly circular while labels give a=4,b=3. Therefore the labeled axes, not apparent aspect ratio, determine radii. Exact source replay retains each original image unchanged; changed parameters use a freshly drawn equal-aspect coordinate system so the shape agrees with its labeled geometry.

3. Components: white background; black axes through origin with arrows only at positive ends; small intercept marks at (±a,0),(0,±b); labels −a,a,−b,b; blue parametric curve (a cos t,b sin t), 0≤t≤2π; bounds derived from a,b; x/y labels away from arrows. Half and quarter values render decimal labels, matching the source reading style. Thin tick marks do not add a grid-reading demand.

4. Specification: render.py uses Matplotlib only, 1201 samples, equal aspect, 840×630 white PNG, no direct SVG. Input data comes from the exact question instance. Labels retain clear offsets for extrema and aspect ratios ≤6. Each deterministic geometry has a PNG and JSON sidecar, including rational radii, intercepts, bounds, runtime and dependency provenance. The existing read-only cached Python3.10/Matplotlib wheels supply rendering because the main Python3.13 venv lacks Matplotlib; no environments are modified. Unique render-input temporary paths and atomic separate PNG/sidecar replacement prevent mixed inputs. Cache hits require both artifacts. Concurrent fresh same/different geometry tests compare raster extents and identical-output bytes. No cache pruning occurs. Validation reads blue-pixel geometry from actual raster files and compares their ratio to independently parsed solution radii. Generated-<level>-contact.png supports visual review of all generated bank/template variants.
