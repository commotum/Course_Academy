# Plot extraction and specification

All 15 distinct original images were opened at full native resolution (360×304) and inspected. `source-geometry.json` records every bank member plus all canonical/source worked plots, hashes, native dimensions, axis origins, labelled coordinates, asymptotes, growth direction, approach side and uncertainty. The bank order was cross-checked against the owning MA widget.

The fixed visual pattern is white background, black x/y axes with positive arrowheads, no grid or ticks, blue unarrowed exponential curve, filled blue marked point, and a coordinate label. Nonzero horizontal asymptotes are black dashed lines labelled y=c. Curve tails are clipped by image bounds, with no finite endpoint marker and no curve arrow. A source curve approaching the x-axis has an unlabelled zero limiting line. Its few-pixel positive residual is not evidence of a different numerical shift. Original images have different origins and apparent scales; they must not share a guessed axes calibration.

The meaningful graph-reading demand comes from labelled coordinates/asymptotes, approach side and increasing/decreasing direction. Neither a numerical exponential base nor exact unlabelled points can be recovered from these rasters. Source bank recipes thus assert feature geometry and preserve exact original images at source parameters; normalized changed-parameter curves use the prompt base explicitly. There are no unlabelled fractional endpoint guesses.

The private Matplotlib renderer plots each choice's own complete curve a b^(s(x-h))+c and verifies its own marked coordinate. Base/stretch/shift solution plots are generated from the same instance. Bounds depend on the asymptote, marked point, origin and amplitude. Horizontal-shift choices mark (k,k+c), without mislabelling that point as a y-intercept. Feature labels use measured final mathtext boxes and the nearest valid placement. Every box clears axes, asymptote, curve, filled marker and other text by bounded pixel margins. There are no background boxes on feature labels. Labels fit inside the final 480×400 PNG, including signed, zero/near-zero, extreme and horizontally translated marker cases. No labels are guessed from source grid increments: there are no increments. Authored difficulty claims are fractional arithmetic claims, not harder unlabeled scale reading.

Assets and JSON sidecars use deterministic spec hashes. Renderer inputs are unique temporary files; each PNG and sidecar is atomically replaced. Both PNG and matching sidecar are required for a cache hit. Source assets are read-only; output lives only here. Concurrent identical/different fresh renders are tested in a unique private temporary directory; caches are not pruned. Actual Python, Matplotlib and NumPy versions, dependency paths if a fallback is required, bounds, axes transform, curve samples, label bounds and PNG hash are recorded in every sidecar. The currently available primary runtime is Python 3.13.5, Matplotlib 3.11.2 and NumPy 2.5.4; the renderer also supports the documented read-only cached Python3.10 fallback if necessary.

Independent validation reads actual displayed equations and plot sidecars, recomputes points and curves, then checks blue strokes in actual PNG pixels under the recorded axes transform. Only natural black axes/asymptote stroke occlusion has a bounded sampling allowance. No curve points are excluded under text; measured boxes are independently checked against the complete recalculated curve. Every review PNG is checked; this is distinct from hashing source assets and from native radio ID grading. Full-resolution visual review also checks labels, orientation and clipping.
