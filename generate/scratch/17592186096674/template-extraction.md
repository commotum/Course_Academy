# Template extraction and bounded parameterization

The mathematical backbone is a full-rank three-variable system already in row echelon form, with unit pivots. The learner clears entries above the z pivot in row 2 and row 1, then clears the y entry in row 1 when nonzero. The requested object is either the full reduced augmented matrix or the unique solution in the observed vector/coordinate form. Preserve supplied equations, request wording, field layout and five-choice response contract separately for these three backbones.

`source-components.json` describes all nine source instances individually: each augmented matrix, ordered exact source bank, correct triple, response shape, source/field-owned answer identities and explicit component recipe. `source.json` retains the original prose and ordered solution matrices. These files are the extraction evidence, rather than a generic description substituted for the sources.

The only variable slot is positive integer scale k in [1,12]. Fixed items are the observed coefficient matrix, three variables in x/y/z order, unit pivots, exact row operation sequence, response shape, source bank profile and supplied/requested roles. This narrow sampling policy retains the same two/three elimination steps and comparable arithmetic. The original scale k=1 is retained for source replay. Normal sampling enumerates all declared k values without replacement using a seed; seed and choice order are not content variation. There are 108 distinct augmented systems before excluding existing or unavailable tasks.

For a source [A|b] and bank triples v_i, generate [A|k b], the correct solution k A^{-1}b and the complete bank k v_i. Each incorrect tuple's exact recipe is recorded as multiplication of its observed ordered triple by k. These are conservative homogeneous expression patterns. The pedagogical origin of individual source errors remains unresolved; no invented misconception is presented. A bank is selected in full before instance construction. Positive k preserves all original distinctness and the unique correct designation. No mixed bank, extra choices, or feedback is introduced.

All solution matrices derive by scaling only the augmented column. Prompt equations, system conclusions, named coordinates and vector conclusions scale together. Row operation coefficients are fixed because A is fixed. The source's explanation and operative stages are retained as parameterized prose: construct augmented matrix; observe row echelon form; transform step by step; when solving, read the resulting system and state the ordered solution. The existing source typo “he solution” is retained as evidence rather than a reason to change source data. Matrix-choice LaTeX had redundant escaping; generated values use ordinary single LaTeX escaping and normalized spacing. Mathematical fidelity is reported separately from these formatting differences.

Validation independently parses the displayed equations and every solution matrix, applies each displayed row operation, checks RREF, solves the linear system, verifies every bank tuple and conclusion, and exercises all 108 declared variants. Every original bank replays with all 45 choices and 36 distractors matched; missing/extra options fail. The actual application `grade_field` accepts each canonical selection and rejects all four incorrect selections. These are radio responses: their mathematics is checked independently, and ID grading checks are reported separately.

No variable target-position slot is declared: all three unknowns remain requested, in source order. A target change would alter the whole-system response contract. Coefficient variation, singular systems, non-unit pivots, fractions, changed operations and higher difficulties are outside this validated package. No plot extraction or generation is required. `review.md` shows every original alongside a concrete scale-3 variant, and `review.json` retains all exact source replays and the full bounded domain.
