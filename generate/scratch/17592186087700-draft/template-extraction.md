# Four extraction stages

1. **Specific observed questions.** `source-cases.json` contains every original MA record in full, and `templates.json` records each original matrix's complete base entries, extracted outer scalar, labels, difficulty, prompt mask, solution mask and ordered product blocks. Original values range from sparse shears through dense signed 3×3 matrices and rational scaling 1/2, 1/3, 1/5, 1/7 and 1/15; the largest original integer magnitude is 17. Hard uses 4×4 matrices with two 2×2 blocks. A failed identity check displays one disproving cell and stars in all remaining cells. A successful check displays the complete identity and then checks the reverse product. Original source IDs and all field-owned choices/designations are retained exactly in source-cases.json.
2. **Generalized pattern.** Multiply each supplied candidate pair. One nonidentity cell disproves the inverse claim. A candidate that is an inverse is verified in both orders. Infer the additional inverse/noninverse statement from the same pair. Preserve the full original wording, order, matrix factorization and conclusion. Easy applies only the canonical single-pair verification with a single supported Boolean field.
3. **Components and banks.** The prompt has three supplied named matrices, sometimes a rational scalar times a displayed integer matrix. Source solutions contain two forward checks and the reverse of each successful check. Every original choice belongs to one of fields I/II/III and is exactly text false or true; its operation is evaluation of that field's stated product/inverse relation. The full bank is always both values, selected as a complete profile before coordinates are sampled. There are no partial choice pools or invented diagnostic feedback. Source `record` retains all original IDs and field presence. `templates.json` gives the original bases, scalars, each block's ordered operand roles, identity status, witness and any factored result scalar, alongside the complete masks. This maps every choice without inventing an error recipe.
4. **Reusable backbone and slots.** The source-shaped masks replace only complete matrices. Permutation and coordinate signs act on every base as S A S⁻¹, where S is a signed permutation matrix. Outer rational scales retain their role and original spelling. The same transform applies to all supplied objects, so all original inverse truth patterns and arithmetic workload remain intact. Each failed block has a variable witness slot: any actual product cell unequal to the corresponding identity entry. Its printed value is derived from that exact product, retaining the original result factor. All prose, complete operand matrices, complete successful results, nonidentity witness, identity size and final statement remain consistent. Choosing a different witness does not count as a new assessed task. Source product roles and inverse-statement polarity are fixed because changing them would alter the three-field relation graph. No source asks for a withheld entry, so withheld-data variation is inapplicable; no additional missing-entry skill is introduced.

Normal API `profile='observed'` means source-shaped complete Boolean bank with the documented minimal repairs; it does not claim original difficulty calibration for transformed variants. `profile='raw-source'` is public parameterized evidence-only replay, including the original malformed operand/reference. Raw source prose is compared after the shared presentation normalization separately from correctness. There is no branch returning a stored source question. Every replay, including anchors, fills the same full masks and calculates its products. Changed-parameter records for every mask are in review.json and reviewed through the same independent printed-content checks.

The easy family has slots ordered off-diagonal position (six), integer shear entry ±1…±5 (ten), and whether B has the inverse sign (two). This gives exactly 120 complete mathematical tasks. It preserves the canonical opening, forward product, reverse product when successful, and inverse conclusion. The failed case uses the observed practice convention of one nonidentity witness. It introduces no computation of inverses by a new method.

Signed coordinates form a finite family: 3!·2³ raw transforms for each moderate source and 4!·2⁴ for each hard source. Global sign and any matrix symmetries duplicate objects; validation counts unique actual rational supplied matrices plus ordered relation roles, excluding labels, transforms, bank profile, witness position and option order. Presentation identity additionally includes actual normalized prompt, full solution, difficulty and complete banks. A label or alias cannot create a mathematical task.

Source-error repairs have a separate denominator: q-7913's AB label becomes AC; q-149820's opening I3 becomes I4; q-7909's second C operand uses the printed prompt's C, with no change to its already-correct displayed witness or answer key. q-149818's `fasle` becomes `false`. Original wrapper and raw replay retain all defects. Neither exact replay nor unchanged final keys count as mathematical proof.
