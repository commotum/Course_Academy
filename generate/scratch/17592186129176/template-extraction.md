# Template extraction

`extraction.json` describes every source separately, including the exact matrix, selected rows, field UUID, answer UUIDs, integer values, and numeric recipes. `source.json` preserves prompt typography, ordered solution stages, original keys, and missing data. `source-fidelity.json` reports replay results.

The common task is to scan each requested row from left to right, identify its first nonzero entry, and sum the resulting two or three signed integers. The matrix is always 4×4. The response is one integer selected from five choices. The solution defines a leading entry, lists the selected rows and their values in order, repeats the matrix, and adds those values. No elimination, row operations, column queries, or equation solving occurs.

The two templates keep their respective two-row and three-row workloads fixed. Slots are the matrix entries, the selected row subset, the leading position in each row, and the bank profile. Row identities are parameter slots: changing which two or three rows are queried preserves the operation, field contract and solution stages. Matrices may be neither triangular nor echelon form. All rows must be nonzero; a zero row would make the requested leading entry undefined. Row indices are sorted and distinct. All 6 pairs and all 4 triples are eligible.

Observed values are signed integers from -9 to 9; zeros occur before and after leading entries. The sampler uses that same numeric range, with independently eligible leading columns 1–4 and no zero rows. This full column/row domain is a conservative same-method generalization. The source's particular selected row or column is not a mathematical restriction. Selected leading entries, ordinal words, their order, the repeated matrix, answer and final sum all derive from one instance. A changed-target test holds the matrix fixed and independently reads all 10 target subsets.

For each source bank let S be its correct leading-entry sum. Each original value V maps to the recipe `S + (V - S_original)`. `extraction.json` stores the actual offset for each choice and its field ownership. The complete five-value source profile is selected before rendering, and no profiles are mixed. These are exact observed numeric patterns; attributing specific learner misconceptions is unresolved. Translating the whole pattern with S is a declared authored generalization, not a recovered cognitive model. All banks contain one correct value and four pairwise distinct incorrect values for every S. No distractor explanations are added to the learner presentation.

Replay uses original parameters and profiles and explicitly preserves source typography. All 12 complete banks match, including all 48 incorrect values. All 10 available original solutions and key designations match. The two missing source keys/solutions are local supported completions for validation only. Normal output normalizes incidental whitespace/punctuation while keeping the complete solution sequence. Exact source wording during replay is distinguished from independent mathematical checks of normal rendered variants.

Question, field, and field-owned answer UUIDs are deterministic. Bank profile is included in authored identity to avoid collisions, but semantic deduplication ignores profiles, seeds and option order. It compares selected row identities, first-nonzero positions and their values, and deliberately ignores changes confined to unqueried rows or entries after a leading entry. The inventory commit additionally excludes canonical-example tasks. Different seeds or choice order alone never count as new inventory.
