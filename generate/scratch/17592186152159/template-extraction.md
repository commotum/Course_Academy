# Four-stage template extraction

## 1. Describe each source before generalizing

`classification.md` records each source's curve/scalar/bounds family separately. `source.json` retains original number forms, notation, whole prompt, every owned answer field/choice/correct record and solution. All fields have key selection and radio type; every bank contains five complete t-integrals. q-76188 has endpoints (0,0),(2,2), rational curve coefficient 1/2 and scalar y/x; q-76189 has bounds 0,e and exponential cancellation. q-148206 has endpoints (0,0),(2,8), cubic graph and xy. q-148208 has positive endpoints (1,1),(2,1/2), reciprocal graph, derivative with a negative sign, rational speed normalized to √(t⁴+1)/t². q-76414 has bounds 0,1, affine graph with slope5/shift2 and exponential scalar. q-148199 has bounds0,2, negative rational slope−1/2/shift2 and a scalar subtraction. q-148205 has bounds0,2, scaled exponential and cosine scalar. q-76415 has endpoints(1,2),(3,18), scaled quadratic and sine scalar. q-76416 has bounds1,2e, logarithm and exp(y) cancellation.

The ordered source solution stages are parametrization; derivative definition; differentiation of complete curve; derivative value; speed definition; squared-component speed; reduced speed (and optional rational normalization); scalar declaration; substitution with optional simplification; symbolic integral setup; substitution integral; optional extraction of constant. The cubic source omits the redundant constant-extraction row. These exact stage counts, prose, punctuation and expressions are retained by each source-specific solution mask, rather than imposing one generic source layout. q-76188 supplies no sequence to recover.

## 2. Shared mathematical pattern and purpose

Set x=t on a graph y=g(x); substitute both coordinates into f; differentiate g; use √(1+g′²) for ds; carry the x interval to t; select the equivalent **complete definite integral**. Stop before evaluating it. Each template is a same-method peer. Full integral values, not merely integrand spelling or bounds, determine mathematical choice equivalence.

## 3. Component and complete-bank map

`observed-templates.json` contains the explicit curve and scalar expressions, source-specific prompt/solution masks, every original integral expression pattern with bound slots, source UUID/MA ID, correct index, endpoint style and original parameters. `bank-map.json` independently parses and lists every source field, original exact choice, reduced integrand, lower/upper bound, exact-replay status and designation presence. This is the exhaustive choice map: 9 banks × 5 options, including both equivalent-wrong-option pairs. No choice is unmatched.

Observed choices are parameterized *expression-pattern recipes*: their complete integrands retain the original constants while their bounds vary. This is a deliberate interpretation limit. Examples such as 4∫t³√(1+t⁴)dt and 2∫t³√(1+9t⁴)dt in the cubic family cannot establish the intended error operation from one sample. No polynomial fit, random answer perturbation or guessed coefficient rule is promoted to normal generation. Bounds and endpoint coordinates vary consistently in the source prompt, all choices, parameterization and every solution integral. Every observed bank is selected as a whole, and accessible through the public evidence profile even if ambiguous.

The separate **authored_operations** complete five-choice bank contains: correct f(r(t))√(1+g′²); omit ds (f(r(t))); omit scalar (√(1+g′²)); omit dx component from speed (f(r(t))√(g′²)); omit square root (f(r(t))(1+g′²)). These are explicit assessed-method mistakes, applied together without a first-valid recipe pool. Different complete integral values are required for every pair. Reject the entire sampled instance on a collision; explicit invalid inputs raise ValueError rather than changing parameters. No distractor diagnosis is shown to learners.

## 4. Reusable templates and consistency calculations

The observed masks are ordinary bound/endpoint templates created from complete subcomponents at extraction time by `build_evidence.py`; runtime has no source-ID lookup or literal source-return branch. Fixed expression patterns, fixed complete bank membership and source-specific prose/stage sequence are retained. Original coefficients are intentionally not freely resampled under an observed bank. The original missing source solution uses the same shared sentences and an authored fixed solution.

Normal templates render the shared instructional sentences, explicit coordinate substitution (including implicit xy), an unevaluated derivative/squared-norm mask, reduced norm and substitution, symbolic integral, multiplication row and final definite integral. Complete TeX components are substituted with a command-aware mask; function commands cannot be renamed accidentally. Natural logarithms print as ln. There are no images or plotting slots.

All authored level guards also apply to explicit inputs. Exact SymPy values are used; random sampling is deterministic. Outer knowledge_point keys are plain db_id/id/title; schema inner keys have colons; enum/UUID strings and correct lookup refs use the local review API. Field/answer UUIDs are owned, stable over option order and seed. Mathematical fingerprint depends only on actual curve, scalar and interval, excludes banks/profile/spelling; presentation identity hashes actual prompt, fixed solution, sorted complete bank and correct value plus version.

## Verification and interpretation limits

`validate.py` independently reads the printed curve, scalar, interval or endpoints, correct complete integral and every displayed solution derivative/norm/substitution/integral stage. It checks 45 exact replay values, complete source prose, 8 present designations, malformed prompt repair, complete-value collisions, both missing-level templates, explicit invalid bounds/coefficient/level failures, deterministic UUIDs, native radio grading and a deliberately mutated printed curve. Exact symbolic polynomial integration catches the signed source collision; high-precision complete numerical integration plus symbolic simplification checks other pairs, including transformed-integral equality. Two concrete source equivalences have independent substitution/primitive proofs above. Numerical comparison is a practical bank distinctness check in this bounded corpus; it is not presented as an analytic theorem for unrestricted functions.
